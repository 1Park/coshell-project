## 사용자 피드백 반영

이전의 모든 후보를 탈락으로 반영했다. 데스크탑+카메라로 핵심 경험이 유지되는 안, MCU에 버튼/LED를 배분한 것을 보드 필요성으로 주장하는 안은 제외한다. 현장 접촉 센싱·이동·분산 배치·지속 제어가 제품 결과에 필수인지 먼저 검토한다.

## 첫 두 묶음에서 확인한 주요 반증

- 인간 간 운반 협조를 위한 촉각 안내, 적응 호스 릴, 가변 음향 패널에는 가까운 선행 사례가 있었다.
- 입자 호퍼 막힘 예측은 원 논문에서 예측 가능한 시간과 성능이 제한됐다. 핵심 시연의 신뢰성이 부족해 제외했다.
- 접착 클램프는 PID, 차양 배수는 고정 경사·배수로라는 단순 대안이 강하다. AI를 추가할 충분한 이유를 만들지 못했다.
- 학습 기반 박리, 부착 방식에 따른 진동 센서 자동 보정, 물리 워터마킹, 초음파 간섭 저감, 로봇 착의 걸림 감지에는 근접 선행이 있었다.
- 출처는 각 후보의 sources에 연결했다. 조회된 모든 검색 결과를 정독했거나 근거로 사용한 것은 아니다.

## 세 번째·네 번째 묶음

N003/N005/N010/N013의 미해결 반론을 재검토해 탈락으로 변경했다. 순차 밸브 시험, 장치 상태 API, 임계값 대기, 즉시 짧게 멈추는 방식보다 나을 구체적인 사용처를 확보하지 못했다. 중단 가능성처럼 센서 신호만으로 알 수 없는 의미도 문제였다.

N019–N028의 10개 안을 추가하고 모두 보관했다. 새로운 기구를 붙이는 것만으로 AI 기여가 생기지 않는다는 점을 재확인했다. 장식용 실의 결함 구별은 실제 제조사 제품, 적응 빗질은 MIT 연구실, IoT 물리 상호작용 분석은 저자 코드와 원 논문으로 가까운 구현을 확인했다.

수채화 국소 습도 제어는 공개 특허가 있으나 실제 제품 구현을 확인한 것으로 세지 않았다. 이 후보의 탈락은 AI가 읽어야 할 국소 수분 상태와 예측 데이터 확보가 미해결이라는 이유다. 테이프 끝 자동 찾기도 일반 자동 디스펜서와 같은 구현이라고 단정하지 않았으며, 초기 걸기 기구와 단순 대안 대비 효용 때문에 제외했다.

[추가 검색 기록](research/v3-round3-4-audit.json)에 검색어 18개와 직접 열람한 3개 페이지를 기록했다. 앞선 28개 검색어와 별개다.

## 다섯 번째 묶음

N029–N039의 11개를 추가 보존했다. 신규 등록과 외부 검색 전에 가까운 과거 ID의 사용자 과제·센서·판단·행동을 대조했고, 변형은 parent_id를 기록했다. 최종 탈락 8개, 조사 중 3개다.

지퍼의 시각/촉각 예측 제어와 편물 자동 해체에는 가까운 공개 구현이 있었다. 지지대 제거 플라이어는 균열 발생 후 감지를 손상 전 예측과 구별하여 탈락시켰다. 보빈 교차 해소는 작은 데모와 실제 많은 실의 문제 사이에 기구 복잡도 차이가 커서 제외했다. 위딩 복구와 제본 클램프도 강한 단순 대안 대비 개선 장면을 확보하지 못했다.

N031/N034/N038은 [조사 카드](research/OPEN_CANDIDATES.md)에 구체적인 루프와 미해결 조건을 적었다. 위험을 나열한 것으로 통과 처리하지 않았다. [검색 메타데이터](research/v3-round5-search-audit.json)는 검색/직접 열람 36개 호출의 기록이다. 여러 검색어를 묶은 후속 매듭 조사 1회는 별도 파일로 추가 보존한다.

## 여섯 번째·일곱 번째 묶음

N040–N053의 14개 버전/스케치를 추가했다. N034의 기존 구상은 같은 ID 안에서 수정하고, N046은 새 안으로 등록했다. 두 안을 설계 검토 통과로 판단했으며 실제 성능을 측정했다고 기록하지 않았다. 나머지 새 13개와 과거 OPEN이던 N031/N038은 제외했다.

구체적인 반증:

- RestPartner: Cyther 원 논문에서 인간/로봇의 타격·감쇠 역할 교환을 확인했다. Snar2는 펠트 패드 자동화를 하지 않았다고 적었으므로 잘못된 자동 감쇠 근거로 쓰지 않았다.
- SinkEscrow: Root/Sepura 제조사가 음식물 분리와 이물질 감지·정지·회수를 설명한다. 직접 열람한 Root 페이지는 사전주문과 2026년 10월 출하 예정도 표시하므로, 출하 완료나 독립 실측으로 표현하지 않았다.
- CutCatch: piSAVE sense의 수동 체크밸브가 노출된 흡착점 누설을 제한하는 강한 대안이다. 정확히 같은 AI 제품이 있다는 이유가 아니라 AI 구역 예측의 추가 효용 부족으로 제외했다.
- BorrowedEar: 콘크리트 바닥/벽 진동에서 소음을 예측한 원 연구와 저가 FSR/고밀도 깔창의 힘 추정 연구를 구별했다. 기존 연구의 오차 수치를 제안한 착용 센서 시스템에 옮기지 않았다. 원 논문의 센서가 어느 층에 놓였는지 확정하지 못했으므로 임시 수신부 철거의 직접 중복이라고 단정하지 않았다.
- WetEdgeContact/WarpRescue: 각각 새 수분 계측과 국소 열·잔류 응력 제어가 응용 시연보다 앞서는 직렬 병목이다. 알려진 물리 원리와 즉시 쓸 수 있는 프로토타입 경로를 구분하여 제외했다.
- SketchPatchboard: Jumperless의 공식 문서에서 실제 연결 변경·계측뿐 아니라 LLM/MCP 자동화도 확인했다. 회로 스케치 인식 추가만으로 새로운 작업을 만들지 못했다.

WindNegotiator는 ‘어떤 배든 AI가 조종’하던 넓은 설명을 ‘사람이 먼저 같은 조건에서 완주한 배’라는 참가 규칙으로 바꿨다. 이 규칙이 제어 불가능한 물체로 이기는 허점을 제거한다. 작은 학습 동역학 모델의 비교군은 교정 PID·선형 모델·간단한 물리 모델이며 무작위 제어만 비교하지 않는다.

Unwrite는 그림을 맞히는 AI, 종이를 흔드는 로봇, 지우고 다시 그리는 미술 로봇과 각각 대조했다. AI가 이미 아는 정답의 단서를 제한된 면적에서 지우고, 사람이 남은 그림으로 다른 사람에게 전달하는 규칙을 핵심으로 삼았다. 인간의 정답과 복구 라운드 수가 결과이며 AI 신뢰도는 이를 대신하지 않는다. 소형 XY 키트의 확보가 전제다.

통과 카드는 [N034](research/N034_WIND_NEGOTIATOR.md), [N046](research/N046_UNWRITE.md)에 14개 조건별 근거를 적었다. 조사를 닫은 후보들의 이전 이유도 JSON의 history와 [5차 카드 보존본](archive/OPEN_CANDIDATES.round5.md)에 남겼다. [6–7차 판정 데이터](research/v3-round6-7-decisions.json)는 이번 상태 변경의 스냅샷이다.

이 단계에서는 새로움의 절대 증명이나 비교군 대비 실측 우월성을 요구한 것이 아니라, 구체적인 사용 흐름·관측 가능한 정보·알려진 구현 경로·강한 비교군에 대한 설계 근거로 판정했다. 추후 실험 실패 시 VALID도 변경한다. 단지 위험 목록을 작성했다는 이유만으로 통과시키지는 않는다.

## 여덟 번째–열 번째 묶음

N054–N069의 16개 버전/스케치를 추가했다. 그중 15개를 제외하고 N069만 OPEN으로 남겼다. 유효 개수는 여전히 2/10이다. 중간 OPEN이던 N054/N057/N060의 이전 판단도 JSON history에 보존했다.

- LabelLock: 삼성의 관리 라벨 인식/코스 제안과 ANY 햅틱 가전 다이얼을 확인했다. 두 제품이 이 조합을 완성했다는 뜻은 아니지만, 추천을 노브 저항으로 옮기는 것의 새 작업 가치가 약해 제외했다.
- FootTypeGuard: 제조사 설명서의 실제 신경망 노루발 인식 기능과 겹친다. 모델을 쓴다는 이유만으로 새 안으로 세지 않았다.
- ReachCanvas/PaletteService: 실제 구강 화가를 위한 전동 이젤·세척 장치 사례를 확인했다. AI가 다음 움직임/색을 추정하도록 추가하면 관측할 수 없는 의도 문제가 생기고, 명시적 선택을 쓰면 기존 흐름에 가까워진다.
- TactileDock: FingerRover는 손가락을 책상 위 목표까지 실제로 운반한다. 단순 진동 안내보다 강한 직접 선행을 찾아 제외했다.
- LaundryPact: PickClothBot은 세탁 조건별 실제 의류 분배를 구현한다. RFID 대신 OCR을 쓰는 차이를 같은 기술이라고 잘못 서술하지 않았으나 사용자 작업의 핵심은 겹친다.
- PageMend/ChainRelease/GraftHold/ThrowPause: 정밀 기구와 가려진 상태, 접목의 장기 결과, 붕괴 이전의 관측 문제가 남는다. 굵은 줄·표준 종이·이미 무너진 점토로 바꾼 시연을 실제 문제 해결로 간주하지 않았다.

[WhisperHeist 상세 카드](research/N069_WHISPER_HEIST.md)는 실제 소리 경로 설계와 이동 청취를 겨루는 안이다. 모터로 이동한 곳의 음성이 입력이므로 카메라 앱은 아니지만, 기존 능동 청취와 iNNk의 조합을 넘어서는지, 작은 가림막에서도 의미 있는 선택이 있는지는 아직 OPEN이다. 위험을 적는 것으로 통과시키지 않았다. Vosk가 작게 실행된다는 근거를 ExecuTorch 배포 완료로 오인하지 않도록 행사 요구와 모델 경로를 구분했다.

[8–10차 검색 메타데이터](research/v3-round8-10-search-audit.json)는 59회 호출에서 반환된 1,014개 링크 항목을 보존한다. 중복 링크가 포함되며, 1,014개 문헌을 모두 정독·검증했다는 뜻이 아니다. 채택한 근거는 각 후보 sources와 카드에 별도로 연결했다.

## 열한 번째 묶음

N070 ReedTune, N071 CoDrawForce, N072 FussyFold를 등록하고 모두 제외했다. 앞서 OPEN이던 N069도 후속 검토에서 제외했다. 현재 120개 기록 중 VALID 2 / REJECTED 118 / OPEN 0이다. 기존 통과 수를 늘리기 위해 기준을 낮추거나 미확인 안을 집계하지 않았다.

- ReedTune: 자동 리드 프로파일러와 인공 발음 장치의 1차 자료를 확인했다. 음향 피드백으로 비가역 절삭을 개선하려면 공기·입술 접촉 조건과 정밀 가공을 함께 안정화해야 한다. 각각의 장비가 존재한다는 사실만으로 짧은 통합 경로가 성립하지 않아 G08/G09/G10 실패다.
- CoDrawForce: MagicPen의 압력 기반 힘 안내 협동 드로잉과 기존 힘 피드백 펜이 가까웠다. 제조사 응용 설명과 특허를 같은 수준의 실측 근거로 혼동하지 않았다. 현재 설명의 새 핵심이 부족해 제외했다.
- FussyFold: ScanNCut의 실제 재료 스캔→도안 배치→입체 상자 부품 절단 흐름과 visionPRO/IRIS의 무늬·결함 인식 배치를 확인했다. 기존 인쇄 포장재를 활용한다는 차이는 있으나, 얇은 종이로 좁힌 경우 사용자의 간단한 보존 영역 지정 대비 의미 인식의 추가 가치가 약했다. 접힘 강도까지 자동으로 판단하는 안으로 넓히면 원래 줄이려던 계측·기구 범위가 다시 커져 제외했다.
- WhisperHeist: 능동 청취에 비밀 단어 점수를 붙인 것 이상의 사용자 선택을 충분히 구체화하지 못했다. ASR이 불필요하다는 뜻은 아니다. 고정 순회 ASR이라는 강한 비교군과 작은 가림막의 제한을 해결하지 못해 제외했다. 같은 완성 게임이 이미 존재한다고 단정하지 않았다. 카드의 이전 OPEN 분석을 지우지 않고 후속 판정을 상단에 추가했다.

## 열네 번째 묶음

BubbleRoute는 이미 붙은 필름을 손상 없이 실제로 복구할 경로를 확보하지 못했다. 자동 필름 부착 제조사가 사후 기포 복구까지 구현했다고 단정하지 않았다. ReelDuel은 힘·타이밍 제한을 붙여도 강한 단순 상대보다 학습이 필요한 전략을 충분히 만들지 못했다. 기존 인간 간 힘 보정 시스템을 AI 상대의 직접 구현으로 오인하지 않았다.

StillPaper는 실제로 작은 모델을 학습해 초기 가설을 검사했다. [공개 데이터](https://doi.org/10.24432/C5Q01S)의 `hw_dataset` 40개 파일만 사용했고, 전체 안내의 77명을 평가했다고 하지 않았다. 각 분할은 학습/검증/평가 파일 24/8/8개이며, 5회 동안 각 파일이 평가에 한 번씩 등장한다. 리샘플링과 필터는 인과적으로 적용하고 입력 정규화도 과거 구간만 사용했다. 파일 분리를 개인 신원 연결의 독립 검증과 동일시하지 않았다.

8,577개 매개변수 MLP의 기록별 정규화 RMSE 평균은 0.5680, 선형 ridge AR은 0.5805였다. 상대 평균 감소는 약 2.16%, 기록별 상대 감소 중앙값은 약 0.78%이며 40개 중 29개에서 MLP가 낮았다. 고정 복사나 무작위 제어만 비교하지 않았다. 첫 분할을 본 뒤 분할 민감도를 확인하기 위해 나머지 네 번을 추가했고 그 사이 모델 구조·필터·예측 시간을 바꾸지 않았다.

이 결과는 필터링된 좌표의 미래 예측이다. 자발/불수의 운동의 정답 구분, 종이와 펜의 접촉 마찰, 모터 지연, 실제 잉크 선의 개선, 의료 효과는 검증하지 않았다. 신경망이 원리상 불필요하다는 증명은 아니지만, 현재 안의 작은 추가 이득과 남은 고속 센싱/기구 통합 부담 때문에 G06/G09/G11/G13에서 제외했다. [코드·가중치·결과·재현 설명](research/prototypes/stillpaper/README.md)은 모두 보존했다.

## 열다섯 번째 묶음

N086 PunchPartner, N087 FaultCounterexample, N088 ReachLayout을 등록했다. N086은 설계 검토 통과, 나머지 두 안은 제외했다. 현재 136개 중 VALID 3 / REJECTED 132 / OPEN 1이다. 체크리스트를 바꾸거나 OPEN을 통과 수에 포함하지 않았다.

PunchPartner는 동일 실물 악보에 사람이 음을 추가한 뒤 기계가 다시 읽어 조건부 작곡과 천공을 반복하는 세션이다. 자동 천공, AI 오르골, 물리적 공동 작곡 자체에는 각각 선행이 있음을 확인했다. 이미 존재하는 곡 출력 버튼을 차별점으로 쓰지 않고, 실제 손수정이 다음 생성의 제약으로 돌아오는 작업에 범위를 고정했다. 15음·32칸·세 번의 교환, 시판 펀치 전체와 기성 XY 이동대로 제한한다. 직접 금형 제작과 전용 급지기 개발을 제외했고, 조달 전제와 11–16시간의 순차 작업 추정을 카드에 기록했다.

[독립 작은 모델](research/prototypes/punchpartner/README.md)을 실제 학습했다. 초기에는 서로 다른 BWV 악장 번호 사이의 같은 선율 창이 학습/평가에 겹쳤다. 이 문제를 발견하고 원래 결과·가중치를 `.initial` 파일로 보존한 뒤, 같은 창을 공유하는 악장들을 연결 성분으로 묶어 재학습했다. 모델 구조·epoch·마스킹 비율은 바꾸지 않았다. 최종 분할은 학습/검증/평가 406/68/52개 창, 정확한 창의 분할 간 중복 0개다. 같은 음악적 원형의 모든 변형까지 배제했다는 뜻은 아니다.

71,120개 매개변수 모델은 확률 손실 1.0116으로 2차 Markov 브리지의 1.3008보다 낮았다. 그러나 실제 음 위치의 최빈 정답률은 11.45%로 Markov의 25.11%보다 낮았다. 두 결과를 함께 보존하며 생성 음악의 청취 품질 우세를 주장하지 않는다. 초기 독립 최빈 선택 디코더가 같은 음을 반복한 점도 남겼다. 기존 음 보존은 모델의 추론력이 아니라 출력 제약 코드가 보장한다.

후속으로 실제 **ExecuTorch 1.5.1 / XNNPACK** 내보내기와 로컬 macOS ARM64 CPU 런타임 추론을 실행했다. `.pte`는 318,400바이트이고 52개 입력에서 PyTorch 대비 최대 logit 절대 차이는 약 2.38e-6이었다. [코드·결과·로그](research/prototypes/punchpartner/executorch_report.json)를 남겼다. 로컬 실행 성공은 보드/NPU 속도, 펀치 구동, 오르골 음질, 공동 작곡의 재미를 실측한 결과가 아니다.

G06의 설계 통과는 학습한 음악 문맥을 조건부 생성에 사용하는 역할, 관련 위치 제약 생성 연구, 작게 구현·실행되는 경로에 근거한다. 한 개 벤치마크 점수나 모델 크기만으로 재미를 검증했다고 하지 않는다. 기구와 실제 재교환이 실패하거나 강한 비교군과 경험 차이가 없다면 상태를 다시 바꿀 수 있다. 기존 두 통과안과 같은 설계 검토 수준을 적용했다.

FaultCounterexample은 실제 하드웨어와 시뮬레이션 튜터를 동일하다고 오인하지 않았지만, 제한된 회로에서 AI가 자연어 메뉴 선택으로 축소되고 새 실습 가치가 부족해 제외했다. ReachLayout은 수동 초기 배치에 비해 반복 모터 재배치의 이득이 불명확하고 사용자 습관과 기구 부담을 늘려 제외했다.

N082에는 FluidLab과 실제 점성 제트 제어 연구를 추가 확인했다. 실제 물리 유체 제어가 가능하다는 일반 근거이지, 여덟 영상 기준점만으로 도막 상태를 충분히 추론하거나 선형 비교군을 이긴다는 증거는 아니므로 OPEN을 유지한다.

GitHub/PyPI HTTP 조회와 격리 환경 패키지 설치는 별도다. 사용자 후기 검색은 미충족 수요 탐색에만 사용하고 기술적 구현 가능성의 증거로 사용하지 않았다.
