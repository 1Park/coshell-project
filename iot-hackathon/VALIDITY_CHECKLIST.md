# 새 후보의 유효성 체크리스트 — v3

2026-10-04. 사용자 판정에 따라 기존 후보는 모두 탈락, 시작 시 유효 후보 **0개**다. 목표는 아래 조건을 모두 통과한 새 후보 **10개**다. 미확인 후보는 개수에 넣지 않는다.

## 먼저 적용하는 탈락 조건

각 항목은 PASS / FAIL / OPEN으로 기록한다. 하나라도 FAIL이면 탈락 또는 핵심을 바꾼 별도 버전으로 등록한다. OPEN은 조사 대기이며 통과가 아니다. 점수 합계로 필수 조건 실패를 상쇄하지 않는다.

| 코드 | 질문 | 통과에 필요한 기록 |
|---|---|---|
| G01 누적 중복 | 이미 검토한 것의 새 이름인가? | 생성 직후 누적 목록 검색, 가장 가까운 ID와 핵심 차이. 사용자·센싱·판단·물리 행동이 같으면 중복 |
| G02 사용자 가치 | 누가 어떤 반복되는 실패·수고를 줄이는가? | 구체적 작업 전후, 실제로 달라지는 결과. 새로운 설명이나 보고서만 추가한 것은 불충분 |
| G03 복잡도의 이유 | 단순 알림·카운터·원격 스위치를 넘어서는가? | 숨은 상태 추정, 서로 다른 제약 조정, 적응적 물리 개입 중 사용자에게 필요한 기능 |
| G04 임베디드 필요 | 데스크탑+카메라로 바꾸면 무엇이 실질적으로 안 되는가? | 현장 접촉 센싱·이동·분산 배치·지속 제어 중 필수 요인. 버튼/LED 추가, 작음/쌈/오프라인만으로 통과 불가 |
| G05 IoT 구조 | 물리 세계와 연결된 장치의 역할이 핵심인가? | 센서→현장 추론→물리 행동/기기 간 조정→다시 센싱의 구체적 흐름. 네트워크 대시보드는 부가 기능 |
| G06 AI 기여 | 같은 센서의 규칙·임계값·PID·상태 머신보다 학습이 왜 유용한가? | 가장 강한 단순 비교군, 변동 조건에서 그 방법의 한계, 학습 모델이 담당하는 부분. 연출을 위해 복잡하게 하지 않음 |
| G07 외부 중복 | 같은 문제와 핵심 사용 흐름을 이미 구현한 기업/공개 프로젝트가 있는가? | 기능 검색과 반증 검색, 가장 가까운 1차 출처, 중요한 차이. 보드·가격·대상만 바꾼 복제 탈락 |
| G08 관측 가능성 | 필요한 숨은 상태를 센서에서 실제로 구별할 수 있는가? | 관측량, 혼동 상황, 이를 구별할 독립 신호나 능동 시험. 없는 정보를 AI가 추측하게 하지 않음 |
| G09 구현 범위 | 행사에서 핵심을 끝낼 수 있는가? | 최소 부품·입출력·모델·학습 라벨·기구. 범용 로봇, 신규 정밀 계측기, 큰 데이터 수집을 동시에 요구하면 탈락 |
| G10 임계 경로 | 기구→데이터→학습→통합의 순서가 감당 가능한가? | 순차 작업과 실제 중단 시점. 팀 인원으로 직렬 의존성을 지우지 않음 |
| G11 시연 정합성 | 작은 데모가 실제 사용자 문제와 같은 원리·결과를 보이는가? | 시연에서 유지하는 어려운 조건과 직접 측정할 사용자 결과. 포장 변위→배송 안전 같은 대리지표 점프 금지 |
| G12 재현성 | 희귀한 오류나 우연한 볼거리가 없어도 시연되는가? | 반복 가능한 입력·물리 현상과 실패 판정. 핵심 현상 자체가 미확인이면 OPEN |
| G13 반론 대응 | 가장 강한 탈락 논리에 실질적인 답이 있는가? | 남은 반론, 설계 변경 또는 근거. 위험을 적기만 하고 해결했다고 하지 않음 |
| G14 포트폴리오 | 이미 통과한 후보와 실질적으로 다른가? | 서로 다른 사용자 과제와 물리 원리. 같은 제어기에 소재·장소만 바꾼 10개 금지 |

## 증거 수준과 정직한 판정

이 작업은 아이디어 연구다. 설계 유효성은 사용 흐름, 기술 원리의 1차 근거, 부품/데이터 경로, 강한 비교군과 반론 검토로 평가한다. 실제 기기를 제작·검증한 것처럼 기록하지 않는다. 실측하지 않은 속도·정확도·비용은 목표/추정으로 표시한다.

다만 **성립 여부가 전혀 확인되지 않은 새 물리 현상**, **AI가 없는 정보를 맞혀야 하는 설계**, **예외적인 실패 발견에만 기대는 시연**은 실험 전 통과시키지 않는다. 일반적인 구현 조정 위험과 핵심 원리의 미확인을 구분한다. 외부 검색은 신규성 보증이나 특허 조사가 아니다. 근접 선행이 해결하는 사용자 행동과 제안의 차이를 검토한다.

## 생성·소거 절차

1. 한 문장 후보를 만들자마자 누적 목록을 검색한다. 사용자/문제, 센서, 모델 역할, 물리 행동, 결과의 다섯 항목으로 비교한다.
2. 모든 후보를 ID와 함께 등록한다. 중복이어도 삭제하지 않고 `DUPLICATE_OF`를 남긴다. 핵심을 틀면 `PARENT_ID`를 남긴 새 항목이다.
3. G01–G06으로 내부 선별한다. 초기 탈락도 이유와 함께 보관한다.
4. 남은 후보를 외부 선행·물리 원리·부품/데이터 관점에서 조사한다. 가까운 사례를 의도적으로 찾는다.
5. G07–G14와 적대적 재검토를 적용한다. 모든 필수 항목이 통과해야 유효 개수에 넣는다.
6. 10개가 되기 전에는 목표 달성을 선언하지 않는다. 기존 탈락안을 이름만 바꿔 채우지 않는다.

원래 사용자 기준: 너무 단순함, 너무 뻔함, 기존 공개 프로젝트/기업과 중복, 너무 넓음. 추가 사용자 기준: 데스크탑+카메라로 핵심이 유지되는 안 제외. 리뷰 근거: [ADVERSARIAL_REVIEW.md](ADVERSARIAL_REVIEW.md).
