# N086 PunchPartner — 같은 종이 악보에 사람과 AI가 번갈아 음을 더하는 오르골

2026-10-04 · **VALID — 설계 검토 통과**. 오프라인 모델 학습과 로컬 CPU ExecuTorch 실행까지 확인했다. 실물 천공·보드 실행·청취/사용자 평가는 미실시다. 아래 초기 OPEN 분석과 후속 판정을 함께 보존한다.

## 바뀌는 사용자 작업

사용자는 종이 오르골 악보의 앞·중간·끝에 원하는 음을 직접 몇 개 뚫는다. 기계는 실제 구멍을 읽고 그 음들을 바꾸지 않는 짧은 선율을 제안한다. 한 번에 네 음만 **그 종이에 직접** 추가한다. 사용자는 들어 보고 다른 빈 자리에 음을 더한 다음 같은 종이를 다시 넣는다. 세 번의 교환으로 작은 실물 악보를 함께 만든다.

악보를 처음부터 완성한 뒤 출력하는 작업과 달리, 손으로 한 추가가 다음 생성의 제약으로 돌아온다. 디지털 편집기를 따로 유지하거나 손으로 바뀐 악보를 MIDI로 옮길 필요가 없다. 목표는 공동 작곡 놀이와 손으로 돌려 들을 수 있는 결과물이다. 음악 교육 효과나 전문 작곡 품질을 주장하지 않는다. 구멍은 테이프로 막을 수 있으므로 ‘취소가 절대 불가능하다’를 가치로 내세우지 않는다.

## 최소 범위

- 시판 15음 종이 오르골 한 종류, 단선율, 32개 시간 칸, 세 번의 교환. 임의 길이·여러 악기·오디오 채보는 제외한다.
- 기존 구멍이 있는 칸의 음은 고정한다. 사람이 빈 구간에서 AI가 채워도 되는 범위를 직접 지정한다. 두 음이 겹치거나 기구의 연타 간격을 어기는 입력은 구멍 위치와 이유를 표시하고 진행하지 않는다.
- USB 카메라와 역광으로 구멍을 검출한다. 이 단계에는 고전 영상 처리를 쓴다. 모델의 역할은 앞뒤에 흩어진 고정 음 사이에 어울리는 선율을 만드는 것이다.
- 최소 기구는 기성 XY 이동대에 고정한 짧은 종이와 **시판 수동 펀치 전체를 누르는 나사 구동 압착기**다. 롤 급지기, 자체 펀치/금형 제작, 자동 테이프 수리는 만들지 않는다. 종이 폭 전부에 닿는 펀치 깊이와 이동 범위가 부품 선정의 필수 조건이다.
- 실제 천공 결과를 재촬영한다. 목표 구멍이 없거나 종이가 밀리면 다음 구멍으로 진행하지 않는다. 재삽입한 종이는 이전 명령 목록이 아닌 새 영상으로 상태를 복구한다.

## 누적 중복과 외부 반증

등록 전 N047 CrankCompanion, R08 Foley, N042 RestPartner, N046 Unwrite, N070 ReedTune과 대조했다. 템포 추종 반주·타격음 조정·그림 소거·리드 가공과 달리, 사람이 바꾼 물리 악보를 다시 읽어 음악적 제약으로 삼고 같은 악보를 계속 가공한다. N047에서 작곡 대상으로 방향을 바꾼 후속 후보로 기록한다.

- [Arduino의 자동 오르골 천공기](https://blog.arduino.cc/2019/11/25/play-tunes-on-an-arduino-powered-hole-punching-music-box/)는 이미 실제로 존재한다. 천공 자동화 자체는 차별점이 아니다.
- [Josh Sheldon의 제작 기록](https://jshel.co/blog/music-box-hole-punch)은 자체 펀치 금형 정렬과 충분한 구동력 확보에 여러 번 실패했다고 설명한다. 이 때문에 시판 펀치를 통째로 사용하고 나사로 누르는 구조로 좁혔다. 기존 부품을 구했다는 사실과 자동 압착 지그가 이미 완성됐다는 주장은 구분한다.
- [Music Box Melodies의 AI 도구](https://musicboxmelodies.com/ai/)는 AI 작곡·편집과 인쇄 가능한 악보를 제공한다. 일반 AI 곡 출력은 이미 공개된 흐름이다.
- [Forever Frequencies](https://macmillan.studio/forever-frequencies)는 질문에 답해 생성한 음악을 실제 기계 오르골로 들려준다. AI 음악과 물리 악기를 결합했다는 주장만으로 신규성을 세지 않는다.
- [Grain as Note](https://eccv-art-26.github.io/pieces/grain-as-note-a-bio-tangible-interface-for-interspecies-co-c/)는 사람의 곡물 배치와 닭의 쪼기를 종이 천공·오르골 연주로 연결한다. 이미 물리적 공동 창작과 천공을 결합했다. 본 후보에 남는 차이는 **사람이 직접 바꾼 동일 악보의 기존·미래 음을 읽어 보존하며 빈 부분을 생성하고 재교환하는 편집 흐름**이다. 닭을 AI로 바꿨다는 설명으로 차별화하지 않는다.
- HarmonyQuest의 [소개](https://harmonics.games/how-it-works)에는 AI와 실물 악보가 등장하지만, 확인한 [생성 화면](https://harmonics.games/create)은 Coming soon이었다. 이미 출시된 생성·천공 통합 장치라고 과장하지 않는다.

## AI와 구현 경로

[Anticipation-RNN 연구](https://arxiv.org/abs/1709.06404)는 앞뒤 위치에 사용자가 고정한 음을 만족시키는 단선율 생성을 다룬다. 일반적인 왼쪽부터 다음 음 생성과 필요한 기능을 구별한다. 기존 음 보존·음역·연타 제한은 모델에게 믿고 맡기지 않고 출력 마스크로 강제한다.

공개 [연구 저장소](https://github.com/Ghadjeres/Anticipation-RNN)에는 약 8MB 가중치가 있지만, 조회한 저장소에 라이선스 표기가 없고 Python 3.6/PyTorch 1.0 코드다. 이를 최신 ExecuTorch에서 즉시 실행·배포 가능한 모델이라고 쓰지 않는다. 초기 검토에서는 독립 구현의 작은 마스킹 선율 모델과 music21의 Bach 코퍼스 경로를 별도로 확인하기로 했다. 실제로 수행한 후속 학습·실행 검사는 아래에 기록한다.

강한 비교군은 같은 고정 음·음역·연타 제약을 쓰는 양방향 Markov 브리지와 음계/종지 규칙이다. 학습 모델은 제약 만족 자체가 아니라 떨어진 동기와 프레이즈 연결을 담당한다. 비교는 동일 시드의 실제 오르골 결과에 대해 사용자가 다음 교환을 계속하고 싶은지와 선율의 연결감을 평가한다. 확률 점수만으로 음악 품질을 증명하지 않는다.

## 후속 범위 결정과 실제 검사

**핵심은 손으로 만드는 공동 작곡 세션**으로 고정한다. 전문 작곡기를 대체하거나 12개 음을 사람보다 빨리 뚫는다는 효율 주장을 하지 않는다. 사람이 종이를 다시 편집했을 때 기계의 이전 파일과 어긋나도, 실제 구멍이 다음 턴의 정답 상태다. 두 번째 턴부터 재스캔을 생략하고 원래 MIDI만 계속 출력하면 이 아이디어의 시연으로 인정하지 않는다. 사람도 곡 전체를 미리 완성하지 않고 자기 음을 상대의 추가에 맞춰 바꾼다.

기구는 **기성 XY 이동 키트 + 시판 펀치 전체 + 나사식 누름 축**으로 제한한다. 직접 정밀 금형을 가공하지 않는다. 펀치 목 깊이가 모든 음 줄에 닿아야 하며, 종이를 들어 올린 가장자리 고정 프레임으로 아래 받침이 이동대와 충돌하지 않게 한다. 실제 선정품에서 이 조건을 만족하지 못하면 새 금형 개발로 확장하지 않고 기구 단계에서 중단한다. 기성 키트·펀치·별도 전원은 조달 전제이며 행사 제공품이라고 가정하지 않는다.

VENTUNO의 MPU는 영상에서 실제 악보 상태를 복구하고 선율을 생성한다. MCU는 드라이버의 이동·압착·복귀와 리미트 스위치, 덮개 인터록을 처리한다. 누름 축이 복귀하지 않았거나 구멍 검사에 실패하면 이동을 진행하지 않는다. 데스크탑+카메라만으로는 같은 종이에 구멍을 만들고 다음 입력 상태를 바꾸지 못한다. 같은 모터·제어기를 데스크탑에 연결하면 구현할 수 있다는 점은 인정한다.

[독립 구현 프로토타입](prototypes/punchpartner/README.md)에서 71,120개 매개변수의 작은 Transformer를 실제로 학습했다. Bach 코퍼스의 장조·온음계·단선율 창만 사용했으며, 서로 다른 작품 번호에 겹치는 선율 창이 발견되어 연결된 작품을 같은 분할로 묶고 재학습했다. 최초 결과를 지우지 않았다. 최종 학습/검증/평가는 406/68/52개 창이고 정확한 창의 분할 간 중복은 없다. 음악적 원형까지 완전히 분리했다는 주장은 하지 않는다.

평가에서는 NN의 확률 손실 1.0116, 앞뒤 제약을 모두 사용하는 2차 Markov 브리지의 손실 1.3008이었다. 반면 실제 타격 음 위치의 최빈 정답률은 NN 11.45%, Markov 25.11%였다. **좋은 음악이라는 증거가 아니다.** 원곡 복원의 유일한 정답과 새로운 작곡의 가치를 구분한다. 결정론적으로 네 음을 한 번에 고르는 초기 디코더의 반복음 문제도 기록했다. 시연용 디코더는 순차 조건부 샘플링으로 음을 추가하고, 같은 시드·같은 추가 수의 Markov 버전과 실제 청취로 비교해야 한다. 음역과 기존 음 보존은 언제나 코드로 강제한다.

모델은 이어서 **ExecuTorch 1.5.1의 XNNPACK 내보내기와 Python 런타임에서 실제로 실행**했다. [결과](prototypes/punchpartner/executorch_report.json)에 52개 입력의 PyTorch 출력과의 수치 비교, 파일 크기, 로컬 환경을 보존한다. 이는 작은 모델의 배포 경로에 대한 실증이며 VENTUNO·NPU·물리 기구 성능을 실측한 것으로 표현하지 않는다. [공식 내보내기/런타임 절차](https://docs.pytorch.org/executorch/stable/getting-started.html)를 사용했다.

## 임계 경로와 시연의 합격 조건

견적은 기성 이동대와 누름 축 조립 3–4시간 → 한 구멍의 압착/복귀 및 종이 간섭 검사 1–2시간 → 재삽입 좌표 교정·실제 구멍 확인 2–3시간 → 보드의 모델/MCU 명령 통합 3–4시간 → 실제 세 번의 교환과 비교 2–3시간이다. **11–16시간은 추정이며 제작 실측이 아니다.** 모델 코드가 있다는 이유로 행사 사전 제작 규정까지 확인됐다고 간주하지 않는다.

첫 통합 전에 여러 음 줄에서 반복 천공과 복귀를 검사한다. 종이가 찢기거나 펀치가 끼거나 받침과 이동대가 충돌하면 그 단계에서 제외한다. 이는 미확인 새 물리 원리가 아니라 기존 천공 기구 통합의 위험이며, 미리 합격한 것으로 기록하지 않는다.

직접 시연은 관람객이 새 음을 직접 뚫음 → 재삽입 → 기존 음을 보존한 AI 추가 → 기계식 오르골로 청취 → 사람이 새 위치에 음을 추가 → 다시 스캔하는 세 번의 교환이다. 측정 대상은 기존 음 보존, 새 구멍/실제 소리의 일치, 재삽입 후 손수정 반영, 완료된 교환 수와 소요 시간이다. 공동 창작 만족도·다음 턴을 계속할 의향과 Markov 비교는 사용자 평가 항목이며 미측정이다.
