# N091 KnobSeeker — 실제 아날로그 페달의 음색을 녹음에 맞춰 찾아주는 장치

2026-10-04 · **VALID — 설계 검토 통과**. 최초 OPEN 판단과 남은 실제 검증 범위를 아래에 보존한다. 하드웨어 구현·청취 품질 통과를 뜻하지 않는다.

## 사용자와 정확한 범위

사용자가 참고 기타 녹음을 들려주고, 자기 아날로그 페달과 깨끗한 기타 구절을 연결한다. 기계가 실제 노브를 조금씩 돌리고 그 페달을 통과한 소리를 다시 들으며 가까운 음색의 설정을 찾는다. 완료하면 장치를 떼어도 페달의 물리 설정이 남는다.

첫 범위는 **하나의 오버드라이브/디스토션 페달, 드라이브·톤·레벨 세 노브, 모노 오디오**다. 어떤 앨범의 전체 믹스든 복제하거나 한 페달로 리버브·다중 앰프까지 만들어내지 않는다. 참고는 분리된 기타 소리이며 해당 효과 계열에서 낼 수 있는 톤으로 제한한다. 레벨은 음량 정합 규칙으로, 드라이브와 톤은 학습된 효과 표현으로 찾는다.

중요한 시연 조건은 참고와 입력이 **다른 연주 구절**이라는 것이다. 같은 건조 녹음을 같은 효과에 통과시킨 뒤 파형을 맞추기만 하면 단순 오차 최소화가 강하며 이 후보의 AI 이유가 약해진다. 목표는 음표·리듬 복사가 아닌 효과의 질감과 밝기 설정이다. 모든 참고 소리가 실현 가능하다고 보증하지 않고 가장 가까운 후보들을 실제로 들려준다.

## 누적 중복 검사

R08 Foley, N042 RestPartner, N047 CrankCompanion, N057 LabelLock, N086 PunchPartner와 먼저 대조했다. 물체를 연주하거나 새 곡을 만드는 흐름이 아니라 기존 신호 경로의 설정을 찾는 작업으로 구분했다. 그러나 ‘목표 소리→물리 동작→재측정’이라는 큰 구조가 R08과 겹치므로 이름과 악기만 바꾼 변형인지 최종 판단이 필요하다. R08을 부모로 기록했다.

## 가까운 선행을 숨기지 않기

- [ST-ITO](https://csteinmetz1.github.io/st-ito/)는 학습된 오디오 제작 스타일 거리와 미분 없는 최적화를 사용해 처음 보는 이펙트의 매개변수를 찾는다. 핵심 알고리즘을 새로 발명했다는 안이 아니다. 논문 실험의 Pedalboard/VST는 소프트웨어 이펙트다.
- [Neural DSP의 TINA](https://neuraldsp.com/news/neural-dsp-amplifier-modeling-technology)는 실제 앰프 노브를 로봇으로 돌리고 입출력을 수집해 연속 제어 가능한 디지털 모델을 만든다. 실제 노브+ML 자체도 선행이다. 본 후보는 디지털 대체물을 만드는 대신 사용자가 연주할 원래 장치의 설정을 참고 소리로 찾아주는 흐름이다. 이 차이가 충분한지 G07/G13에서 재검토한다.
- [ADDAC Servo Controller](https://www.addacsystem.com/en/products/standalone/addac-servo-controller)는 외부 노브를 270도 서보와 커플러로 돌리는 제품이다. 회로를 개조하지 않고 노브를 돌리는 구현 경로이며, 소리를 듣고 목표 톤을 찾는 기능까지 제공한다고 설명되어 있지는 않다.
- [후속 ST-ITO 연구](https://arxiv.org/abs/2505.11315)는 임베딩 거리만 최적화하면 비현실적 설정이나 편향된 결과가 나올 수 있음을 지적한다. 임베딩 유사도를 인간 청취와 동일하게 취급하지 않는다. 보컬 효과의 개선 수치를 기타 페달에 옮겨 주장하지 않는다.

같은 최종 하드웨어 흐름을 확인하지 못했다는 것은 세계 최초라는 보증이 아니다. 다른 제품의 구성 요소가 있다는 이유만으로 자동 탈락시키지도 않으며, 조합 뒤 실제 사용자 작업이 달라지는지를 평가한다.

## 물리 제어와 모델

페달 한 대, 270도 서보 3개와 노브/축 커플러, 고정 프레임, 필요하면 노브 위치 마커용 카메라, USB 오디오 입출력, 적절한 기타/라인 레벨 연결, 별도 서보 전원, VENTUNO Q를 가정한다. 실제 페달·인터페이스는 행사 제공품이나 이미 보유한 것으로 가정하지 않는다. 모델은 Linux MPU에서, 각도 제한·서보 구동·정지 처리는 MCU에서 수행한다.

반복 재생한 입력→실물 페달 출력 수집→효과 표현 추론→다음 노브 설정 선택→실제 회전→회전 안정 후 다시 녹음한다. 데스크탑+카메라만으로 실제 신호 경로의 설정을 바꿀 수 없다. 데스크탑에 같은 오디오 입출력·액추에이터·제어기를 달면 구현할 수 있음은 인정한다.

각 노브의 회전 범위는 처음 사람이 끝점 안쪽으로 지정한다. AI가 강제로 끝까지 돌리며 한계를 찾지 않는다. 카메라 마커/위치 피드백으로 명령과 실제 각도의 불일치를 확인하고, 서보가 움직이는 동안의 모터음이나 전기적 간섭 구간을 톤 비교에 넣지 않는다. 실패를 새 효과로 해석하지 않는다.

[AFx-Rep 모델 저장소](https://huggingface.co/csteinmetz1/afx-rep)는 Apache-2.0 표기를 제공한다. 원 체크포인트는 1,156,477,784바이트이며 학습 상태까지 포함한 크기다. encoder는 PANNs Cnn14, 48kHz 입력, 2048 FFT, 1024 hop, 128 mel, 512차원 출력을 사용한다. 이를 1GB의 순수 추론 모델이라고 단정하지 않는다. 전체 패키지의 여러 비교용 모델을 모두 설치·실행할 필요도 없다.

모델 가중치와 저자 encoder 코드를 내려받아 실제 실행 경로를 확인했다. 체크포인트 SHA256: `3587c4f3a1a8ecbc53b8023c480a0e6ff80719bcc26ce6ee6d08b8daf41d75d4`. 후속 [배포 검사](prototypes/knobseeker/README.md)에서 81,905,344개 매개변수 encoder를 ExecuTorch로 변환하고 로컬 런타임에서 실행했다. PTE는 323,418,496바이트, XNNPACK delegate는 7개이며 PyTorch 출력 대비 최대 절대 차이는 약 4.17e-6이었다. 입력은 합성 신호다. 실제 기타 음색 매칭·서보 구동·VENTUNO/NPU 성능을 실측하지 않았다.

## 비교군과 아직 해결하지 못한 조건

같은 탐색 횟수·노브 범위를 주고 (1) MFCC 평균/분산 거리, (2) 여러 해상도의 스펙트럼 거리와 음량 정합, (3) 사람이 같은 구절을 들으며 조절하는 방법과 비교한다. 단순 무작위 노브만 비교군으로 쓰지 않는다. 모델은 프리셋을 추측하거나 물리 각도를 대신 제어하는 것이 아니라, 서로 다른 구절 사이에서 효과의 스타일을 비교하는 부분을 담당한다.

최초에는 G06/G07/G09/G13/G14를 OPEN으로 등록했다. 실제 서로 다른 구절에서 단순 스펙트럼보다 유용한 비교를 제공하는지, 물리 탐색 횟수와 연주 재생 시간이 데모 속도에 맞는지, TINA·ST-ITO·ADDAC 조합보다 설명할 만한 새 사용자 작업이 남는지를 검토했다. 소리 유사도가 올라간 사실만으로 사용자가 원하는 설정을 찾았다고 주장하지 않는다.

## 후속 범위 결정

사용자 과제는 **자신이 계속 쓸 실제 아날로그 장치의 설정을 찾는 것**이다. [ToneMirror](https://www.tonemirror.so/tone-match)와 [TonesMatch](https://tonesmatch.com/)는 사용자가 가진 장비에 맞춘 설정 안내를 이미 제공한다. 본 후보는 장비명을 입력해 레시피를 추천하는 대신 그 개체의 실제 입출력을 반복 측정하며 조절한다. 디지털 효과를 새로 생성하거나 사용자의 페달을 에뮬레이터로 대체하지 않는다. 익숙한 ‘AI 톤 매칭’ 자체를 새 발명으로 쓰지 않는다.

그 차이는 노브 위치를 사람이 옮기는 한 단계의 자동화만은 아니다. 레이블·회로 모델·프리셋 데이터가 없는 페달에서도 실제 응답을 탐색 대상으로 삼으며, 원래 연주할 신호 경로에 결과가 남는다. TINA의 모델 제작 목적, ADDAC의 명령 재생, ST-ITO의 소프트웨어 효과 검색과 비교해 이 최종 사용자 흐름은 조사 범위에서 직접 확인하지 못했다. R08의 물체 타격 음색 합성과도 입력/출력 과제가 다르다. 외부 중복이 전혀 없다는 보증은 아니다.

범용 최적화 연구를 새로 하지 않는다. 첫 구현은 드라이브·톤의 6×6 유효 범위 후보, 각 3초 입력과 0.5초 안정 시간으로 36회 실제 측정한다. **126초는 오디오와 안정 시간만의 계산치**이며 통신·추론·오류 재시도·최종 청취를 포함한 전체 실측 시간이 아니다. 해커톤 목표는 3–5분 탐색이다. 필요하면 같은 36회 예산의 coarse-to-fine 탐색을 쓰되, 단순 비교군에도 같은 후보와 시간을 준다. AI의 역할은 탐색 순서의 마법이 아니라 서로 다른 연주 내용 사이에서 비교할 효과 표현이다.

동일 연주를 틀어보는 것만으로 시연을 통과시키지 않는다. 참고 구절 A와 입력 구절 B를 달리하고, 같은 페달로 낸 숨겨진 설정 세 개를 목표로 사용한다. 목표가 실제로 가능한지 확인하기 위한 조건이며 정답 노브 각도를 모델에 주지 않는다. 후보 셋을 음량을 맞춰 들려준 뒤 사용자가 선택하면 해당 실제 위치로 돌아간다. 하나의 임베딩 최소값을 정답이라고 선언하는 위험을 줄인다. 새로운 참고에 대해 단순 스펙트럼/MFCC와 구별되는 청취상 이득이 없으면 G06을 재판정한다.

## 구현 순서와 직접 결과

기성 페달·USB 오디오 인터페이스·적정 레벨 연결·270도 서보/커플러를 조달한다는 전제다. 행사 제공품이라고 가정하지 않는다. 서보 커플러/프레임과 각도 제한 3–4시간 → 클리핑 없는 반복 오디오 입출력 및 서보 정지 후 녹음 1–2시간 → 보드 encoder 실행/검색 통합 3–4시간 → 노브 복귀·전체 탐색·비교 청취 2–3시간, **직렬 9–13시간 추정**이다. 다운로드/모델 검사 결과가 있다고 행사 사전 제작 허용 여부까지 확인된 것은 아니다.

첫 중단 검사는 한 노브의 제한 범위 왕복에서 미끄러짐 없이 같은 출력 상태로 복귀하는지, 오디오 체인에 반복 가능한 클리핑/험이 없는지다. 페달에 맞지 않는 커플러를 보편 노브 로봇 개발로 확장하지 않는다. 실제 노브 각도 검사는 마커 영상으로 수행할 수 있고, 위치가 틀린 데이터를 음색 모델의 학습 대상으로 삼지 않는다.

시연 결과는 추천 화면 대신 **물리 노브의 이동, 같은 페달로 연주한 최종 소리, 장치를 분리한 뒤에도 유지되는 설정**이다. 기록할 값은 탐색 횟수/시간, 명령 각도와 실제 각도의 오차, 클리핑/실패 횟수, 음량을 맞춘 후보의 청취 선택이다. 분리 후 재생에는 동일 입력·전원 조건을 유지한다. 목표 노브와 정확히 같은 각도만을 성공 기준으로 두지는 않는다. 서로 다른 위치도 유사한 음색을 낼 수 있다.
