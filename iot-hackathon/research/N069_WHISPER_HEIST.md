# N069 WhisperHeist — 이동하는 마이크에게 들키지 않고 단어 전달하기

2026-10-04 · **REJECTED — 11차 후속 검토에서 제외**. 아래는 OPEN 단계의 설계와 미해결 조건을 보존한 기록이다. 현장 실험이나 모델 실행은 하지 않았다.

후속 판정: 기존 능동 청취에 비밀 전달 점수를 더한 것 이상의 사용자 선택을 충분히 구체화하지 못했다. 고정 순회 ASR이 강한 비교군이며, 이를 피하려고 공간·잡음·발성·전략을 확장하면 범위가 커진다. 일반적인 음향 차이는 존재하지만 작은 가림막의 실제 효과를 큰 파티션 연구로 입증할 수는 없다. 동일한 완성 게임이 이미 있다고 주장하지 않는다. 현재 판정은 누적 목록을 우선한다.

## 구체적인 게임

두 사람은 탁자 양쪽의 정해진 위치에 앉는다. 한 사람에게만 무작위 단어 세 개를 보여준다. 정해진 시간 안에 다른 사람이 그 단어를 알아들어야 한다. 암호나 몸짓을 쓰지 않고 실제 단어를 말한다. 사람들은 판·펠트 가림막의 위치를 바꾸어 둘 사이에는 말이 통하고 옆에서는 덜 들리는 배치를 만든다.

AI 상대에게는 정답을 주지 않는다. 탁자 옆 60cm 정도의 레일 위 마이크를 옮겨 듣고 실제로 인식한 단어를 제출한다. 사람 수신자와 AI가 답을 각각 확정한 뒤 정답을 공개한다. 사람이 맞히고 AI가 틀린 단어 수를 점수로 삼는다. AI의 확신도 하락을 사람의 이해도나 보안성으로 취급하지 않는다.

핵심 선택은 비밀 언어를 만드는 것이 아니라 소리의 경로를 만드는 것이다. 마이크에 손을 대거나 완전히 덮는 행동은 금지하고 레일 접근 구역을 비워 둔다. 명칭과 달리 속삭이는 발성 자체의 ASR 약점을 노리는 게임으로 만들지 않는다. 평상시 발성의 작은 목소리와 공간 배치를 사용한다.

## 물리 장치와 학습 모델

이동 USB 마이크 → 온디바이스 음성 인식 → 위치별 후보 단어/인식 안정성 기록 → 다음 청취 위치 선택 → MCU가 모터 이동·끝점·정지 제어 → 모터 정지 후 다시 녹음한다. 모터 소음을 인식 모델이 알아서 제거한다는 의존성을 피한다.

마이크를 이동시키지 않는 데스크탑+카메라는 다른 위치에서 실제 전달되는 음성을 얻지 못한다. 데스크탑에 이동 마이크·모터·제어기를 붙이면 같은 구조를 구현할 수 있다는 점은 인정한다.

음량 임계값은 말이 있는지에는 유용하지만 어떤 단어가 전달됐는지는 판정하지 못한다. 다만 **음성 인식기를 붙인 고정 순회**가 매우 강한 비교군이다. 다음 위치 선택까지 복잡한 학습 정책으로 만들 필요가 있는지는 별도 문제다. MVP에서는 단어 인식이 학습 모델의 역할이며, 탐색은 제한된 후보 위치의 순회/불확실성 기반 선택이다. 이를 새로운 강화학습 기술로 포장하지 않는다.

부품은 기성 1축 슬라이더 키트, 스테퍼/드라이버/외부 전원, 끝점 스위치, 마이크 방진 받침, USB 마이크, 가림막, VENTUNO Q다. 행사 액세서리로 슬라이더를 받을 수 있다고 가정하지 않는다. 자유 이동 로봇과 방 전체 음향 지도는 범위에서 제외한다.

## 가까운 선행과 실질적인 차이

- [Robot Recognizes Three Simultaneous Speech By Active Audition](https://www.jp.honda-ri.com/api/upload/document/entry/20110910/NakadaiK2003-ICRA_4150.pdf): 이동과 음성 인식을 결합하는 기술 자체는 오래된 선행이다.
- [Single-sensor active audition](https://zenodo.org/records/20622100): 소리의 특성을 인식하며 실제 로봇을 움직이는 공개 하드웨어·소프트웨어다. 본 안과 같은 비밀 전달 게임은 아니지만 매우 가까운 능동 청취 기술이다. 페이지의 수치가 우리 보드/마이크 성능이라는 뜻은 아니다.
- [iNNk](https://blogit.itu.dk/pxlab/projects/innk/): 사람이 정보를 전달하면서 AI에게 들키지 않는 목적이 가깝다. 본 안이 성립하려면 표현 암호화가 아니라 **고정된 말의 실제 전달 경로를 설계하고 이동하는 상대를 상대하는 선택**이 충분히 달라야 한다.
- [Whispering Under the Eaves](https://arxiv.org/abs/2504.00858): ASR에 대한 음성 프라이버시 연구다. 이 안에서는 디지털 적대 잡음을 합성하거나 ASR 실패를 보안 보증으로 쓰지 않는다.
- [사무실 파티션 배치 연구](https://pubmed.ncbi.nlm.nih.gov/39296048/): 실제 음성 전달이 배치에 따라 달라지는 근거다. 연구의 1.5m 파티션 결과를 작은 책상 가림막 성능으로 그대로 옮길 수 없다.

## 모델 경로와 일정

[Vosk 소형 모델](https://alphacephei.com/vosk/models)은 작은 로컬 음성 인식의 구현 가능성 근거다. 그러나 Vosk 실행만으로 ExecuTorch 사용을 충족한다고 말하지 않는다. [공식 행사 안내](https://luma.com/executorch-hackathon)는 ExecuTorch 기반 경험을 요구한다.

[ExecuTorch 공식 문서](https://docs.pytorch.org/executorch/stable/)와 [저장소](https://github.com/pytorch/executorch)에 ASR 지원 경로가 있다. 실제 선택 모델·내보내기·AArch64 CPU 실행은 확인 전이다. [공개 Speech Commands 분류기](https://github.com/RF5/simple-speech-commands)를 사용하는 좁은 단어 게임도 대안이지만, 해당 가중치의 라이선스와 ExecuTorch 변환을 검사하지 않았으며 준비 완료로 보지 않는다.

가능한 순서: 손으로 마이크를 옮기는 음향/게임 점검 2시간 → 기성 슬라이더 이동·녹음 분리 3–4시간 → 선택한 ExecuTorch ASR 경로 3–5시간 → 위치 선택과 점수 통합 3시간 → 다른 사람/다른 가림막 배치 점검 2시간. 순차 의존성이 있으므로 앞 두 단계가 안 되면 범용 이동 로봇을 추가해 구제하지 않는다.
