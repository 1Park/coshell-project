# IoT Track 아이디어 — 적대적 리뷰 반영 v2

수정일: 2026-10-04. [리뷰 원문](../ADVERSARIAL_REVIEW.md) · [지적별 대응](../REVISION_RESPONSE.md) · [이전 제안](IDEAS.v1.md) · [추가 조사](../research/revision-sources.md)

**먼저 실험할 안은 ResumeStitch, 그다음은 Live Acceptance다.** 기존 10개를 모두 통과시킨 판단은 철회한다. 두 안은 핵심 사용 흐름을 바꿨고, Physical CI는 예비안으로 재설계했다. 나머지 7개는 현재 출품 추천에서 제외한다.

보드 실행, 물리 실험, 사용자 테스트는 수행하지 않았다. ‘설계에서 없앤 위험’과 ‘실험으로 확인해야 하는 위험’을 구분한다. **괜찮은 아이디어 10개를 확보했다는 기존 결론은 현재 유지할 수 없다.** 아래 우선순위도 출품 확정 순위가 아니라 사전 검증 순위다.

## 1. ResumeStitch — 며칠 전에 멈춘 십자수, 실물을 읽어 다시 시작하기

**피치: “도안에 어디까지 했는지 안 적혀 있어도, 수틀을 올리면 완성한 칸과 다음에 놓을 수 있는 한 땀을 보여준다.”**

### 사용자와 핵심 변경

작업 중 진행 표시를 빠뜨리거나, 다른 곳에서 이어 하거나, 며칠 쉬고 돌아온 십자수 작업자가 대상이다. 현재 실물과 도안을 다시 대조하는 시간을 줄인다. 작업 중에는 관여하지 않고 **재개할 때 사용자가 한 번 요청**한다.

완성된 앞면만으로 마지막 땀의 순서를 알 수는 없다. 그 정보를 추정하지 않는다. 완성 칸을 도안에 반영하고, 사용자가 고른 영역의 다음 미완성 칸을 제안한다. 뒷면 연결·최단 undo·바늘 경로를 삭제하면서 원안의 관측 불가능성과 매 땀 작업 중단 문제를 없앴다.

### 실제 사용 흐름과 시연

1. 일부 작업한 천과 진행 표시가 누락된 도안을 준비한다. 표시 누락이 적용 조건임을 공개한다.
2. 사용자가 자리를 비운 뒤 수틀을 돌려 다시 올리고 풋버튼을 누른다.
3. 원단 격자와 도안을 맞추고, 완료·미완성·확인 필요 칸을 보여준다. 흐리거나 가린 칸은 완료로 채우지 않는다.
4. 사용자가 불확실한 칸만 확인하고 작업 영역을 고른다. 실물 확대 영상과 도안에서 같은 칸을 강조한다.
5. 실제 천에 이어서 한 땀을 놓는다. 발표에서는 **수틀을 올리기부터 올바른 첫 땀까지**를 보여준다.

최소 범위는 **일반 14-count Aida 천, 진한 실 한 색, 24×24칸 안의 작은 도안 하나**다. 약 44×44mm의 실제 작업 영역을 근접 촬영한다. 큰 플라스틱 격자로 대체하지 않는다. 여러 색·큰 작품·심한 원단 접힘은 제외하지만, 이 범위에서도 실제 수공예의 재개 과제는 남는다.

### 어디까지 만들 수 있는가

| 요소 | 최소 구현 | 경계 |
|---|---|---|
| 촬영 | 근접 초점이 맞는 USB 카메라, 받침, 확산 조명, 풋버튼 | 보유 웹캠의 근접 촬영 성능은 미확인 |
| 정렬 | 수틀 외부 기준점 + 원단 구멍 격자; 처음에 도안 원점 확인 | 표식만으로 천의 모든 변형을 해결하지 않음 |
| 인식 | 작은 셀 CNN으로 빈 칸·완성 X·반땀/판독 불가 구분 | 과거 동작 순서와 뒷면 연결은 복원하지 않음 |
| 안내 | 실물/도안 대응, 불확실 칸 확인, 다음 미완성 칸 선택 | 다음 칸은 마지막 바늘 위치나 최적 바느질 순서가 아님 |
| 보드 | Linux에서 로컬 추론·화면, MCU에서 버튼·조명 | 자동 바느질·프로젝터·모터 없음 |

정렬과 다음 칸 선택은 기하·규칙이다. AI의 가능한 이점은 원단 결·실 방향·조명 차이에도 셀 상태를 읽는 부분뿐이다. **정렬 후 임계값·선분 검출로 충분하면 AI 프로젝트로는 약하다는 평가를 받아들인다.**

### 강한 비교군과 검증

제품 비교군은 **진행을 잘 표시한 종이/앱 도안**, 그리고 **진행 표시가 누락된 도안** 두 가지다. 전자보다 항상 좋다고 주장하지 않는다. 표시 누락 사용자에게만 유리하다면 타깃을 그렇게 한정한다. [Pattern Keeper](https://patternkeeper.app/)와 [Knyt](https://www.knytstudio.com/progress-tracker)는 이미 진행 관리를 제공한다. 차별화 가설은 실물에서 현재 상태를 읽어 기록과 맞추는 작업이다.

기술 비교군은 **같은 정렬·같은 이미지의 임계값/선분 판독기**다. 단순 방법도 개발 세트에서 조정한다. 아래 수치는 달성 성능이 아닌 내부 선택 기준이다.

- 원단·촬영 세션 단위로 개발/평가를 분리한다. 보류한 천 최소 2장, 회전·재배치를 달리한 독립 촬영 12회로 초기 평가한다. 인접 프레임을 양쪽에 넣지 않는다.
- 평균 셀 정확도 외에 **촬영마다 틀린 확정 칸 수, 확인할 칸 수, 확인 시간**을 기록한다. 높은 평균만으로 사용성을 판단하지 않는다.
- 초기 기준: 12회 중 10회 이상에서 틀린 확정 칸 0개. 사용자 확인 후에는 올바른 재개 위치여야 한다. 불확실 칸을 늘린 비용은 확인 시간으로 반영한다.
- 십자수 경험자 최소 3명, 각 방식 3과제의 작은 교차 비교를 한다. 비슷하지만 서로 다른 도안과 순서 교대로 기억 효과를 줄인다. 배치·촬영·수정까지 포함한 **전체 재개 시간 중앙값 30% 감소, 잘못된 첫 땀 증가 없음**을 초기 기준으로 삼는다. 이 표본으로 일반 사용자 효과를 입증했다고 표현하지 않는다.
- CNN이 단순 영상 처리보다 잘못된 확정 판정이나 재개 시간을 개선하지 못하면 AI 필요성은 미입증이다. 사용자 효용과 트랙 적합성을 별도로 판정한다.

### 임계 경로와 중단점

**실제 천의 초점·해상도 → 격자 정렬 → 단순 판독 → 사용자 흐름 → 드러난 판독 실패에 CNN 적용 → 보드 배포 → 사용자 비교.**

첫 2시간에는 실제 원단이 충분히 보이는지, 다음 2시간에는 재배치 후 정렬이 반복되는지 확인한다. 다음 최대 4시간에 단순 판독과 작은 CNN의 필요성을 평가한다. 이는 보장 공수가 아니라 추가 투자를 멈추는 시점이다. 실패하면 플라스틱 격자로 바꿔 성공 처리하지 않는다. 첫날 핵심 입력이 확보되지 않으면 UI 고도화에 들어가지 않는다.

**남은 반론:** 스마트폰 기능으로도 구현할 수 있어 VENTUNO Q의 필연성은 높지 않다. 작업등·풋버튼과 결합한 상설 재개 스테이션의 편의성은 가설이다. 동일한 실물 자동 판독 제품이 없는지도 확정하지 못했다. 현재는 사용자 문제가 가장 명료한 검증 우선안이다.

## 2. Live Acceptance — 옮겨 설치한 비전 장치를 지금 보는 실물로 확인하기

**피치: “어제 통과한 모델을 오늘 다른 책상에 설치했을 때, 지금 카메라와 조명으로도 검사할 수 있는지 확인하는 휴대용 지그.”**

### 주제를 어떻게 바꿨는가

사용자는 비전 데모·소형 검사 스테이션을 옮기는 개발자다. 모델 파일이 같아도 초점, 장착 각도, 주변광은 달라진다. 과거 사진을 재생하는 회귀 테스트는 **현재 광학 경로를 거치지 않으므로** 설치 상태를 확인하지 못한다.

희귀한 FP32/INT8 불일치 찾기와 원인 자동 진단을 삭제한다. 모델은 한 개다. 기준 실물과 정답으로 현재 설치의 작업 성능을 확인하고, 조명으로 회복 가능한 경우에만 설정을 제안한다. 조명 탐색은 전수 조사이며 AI는 검사 대상 모델이다.

### 최소 과제와 시연

부품 트레이의 외형이 비슷한 부품 3종을 구분하는 소형 분류기 하나를 대상으로 한다. **정상 환경에서 이미 작동하는 모델과 실물을 확보할 수 있을 때만 선택한다.** 분류기와 검증 장비를 동시에 처음부터 만드는 일정은 채택하지 않는다.

자동 회전대 대신 사람이 교체하는 위치 고정 트레이를 쓴다. 정답은 사전에 사람이 등록한다. 식별 마커는 기록 연결에만 쓰고 모델 입력에서 제외한다. 클래스별 위치를 바꿔 배경·위치만으로 정답을 읽는지도 확인한다.

1. 원래 설치에서 실물 검사와 저장 이미지 검사가 모두 통과한다.
2. 카메라를 다시 장착하거나 주변 조명 방향을 바꾼다. **재설치 상황을 재현한 개입**임을 공개한다.
3. 저장 이미지 검사는 통과하지만 새로 찍은 실물에서 오류가 나타나는지 확인한다. 변화가 없으면 실패를 찾았다고 연출하지 않는다.
4. 정해진 LED 설정 최대 6개를 시험하고 조정용 실물의 오류가 적은 후보를 고른다.
5. 설정 선택에 쓰지 않은 실물·배치로 재검사한다. ‘이번 샘플 검사 통과’ 또는 ‘재장착/수동 점검 필요’를 표시한다. 일반적 품질 보증으로 확대하지 않는다.

재설치로 실제 검사 성능이 변하고 일부 변화는 조명 조절로 회복되는지를 보여주는 안이다. 그 현상 자체가 새로운 연구 결과는 아니다.

### 구현과 비교군

필수 구성은 웹캠, 반복 장착 가능한 고정대, 수동 트레이, 밝기 조절 조명·드라이버, 실제 부품이다. MCU는 조명 설정과 안정화 대기, Linux는 캡처·추론·기록을 담당한다. 모터 제작은 제거했다. 자동 노출·화이트밸런스의 제어 가능 여부를 먼저 확인하고 설정을 기록한다.

비교군은 세 가지다.

1. 저장 이미지 검사: 현재 광학 상태를 못 보는 구조적 차이 설명용.
2. 기준 마커 정렬 + 초점·노출·포화 검사: 단순 영상 품질 검사로 충분한지 보는 핵심 비교.
3. **같은 실물과 같은 모델로 사람이 수동 조명 조절·검사를 하는 방식:** 자동화의 실제 시간 이점 확인용.

과거 사진만 이기면 통과시키지 않는다. 실물 샘플로 작업 성능을 검사하는 절차는 이미 [산업 비전 커미셔닝](https://addascan.co.za/resources/vision-commissioning-procedure/)에 포함된다. 이 후보가 살아남으려면 이동형 장치에서 **설정 복구와 재검사에 드는 사람의 시간 감소**가 있어야 한다. 가격·보드 종류만 다른 것은 독창성 근거가 아니다.

### 검증·중단 기준

- 재장착, 주변광 변경, 정상 유지 조건을 미리 정하고 각 4회, 총 12회 초기 실험을 한다. 잘된 장면만 고르지 않는다.
- 독립 정답은 보류한 실제 샘플의 라벨 대비 모델 오류다. 설정 선택용 샘플로 그 설정을 다시 채점하지 않는다. 개체가 같고 배치만 다르면 개체 일반화 대신 배치 재현성 검사라고 표시한다.
- 잘못된 통과, 불필요한 실패, 사람 개입 시간, 전체 시간을 기록한다. 전부 거부하는 정책도 비교한다.
- 내부 기준: 이 작은 시험에서 잘못된 통과 0회, 정상 유지 4회 중 3회 이상 통과, 수동 실물 검사 대비 사람 개입 시간 중앙값 30% 감소. 상용 신뢰도 보증 수치가 아니다.
- 단순 품질 검사로 필요한 오류를 모두 잡거나, 수동 검사도 충분히 빠르면 추천을 철회한다. 조명을 극단적으로 망가뜨려야만 차이가 나도 철회한다.
- 초기 4시간 안에 기존 분류기의 정상 실행과 재장착 실물 검사를 확보하지 못하면 중단. 다음 최대 4시간은 기능 추가보다 비교군 평가에 쓴다.

**남은 반론:** 희귀한 양자화 차이를 기다리는 위험은 없앴지만 의미 있는 재설치 문제와 시간 이득을 얻어야 한다는 실험 의존성은 남는다. 기존 산업 솔루션과 인접하므로 독창성은 약하다. 행사 기술과의 연결을 우선할 때 검토할 두 번째 안이다.

## 3. ResetCheck — 반복 시연 직전, 덜 되돌린 소품 확인

**예비 피치: “다음 관객을 받기 전에, 이전 체험에서 덜 되돌린 소품만 짚어준다.”**

Physical CI의 실패 연결 추정·부분 투입구·구슬 제어를 제거한다. 반복 체험의 시작 상태를 확인한다. 사용자는 부스 진행자, 성공 지표는 다음 시연이 준비 누락으로 중단되는 횟수다. 세 단계 재시험 몇 초를 절약한다는 효용은 주장하지 않는다.

범위는 한 화면의 재설정 대상 4개: 제자리에 돌아온 토큰, 닫힌 래치, 제자리 레버, 비워진 배출 접시. 사용자가 기준 상태를 등록하고 회차 전 버튼을 누르면 빠진 항목을 보여준다. 장면별 상태 인식과 비교 로직을 분리한다. 관측 불가는 준비 완료로 바꾸지 않는다.

**제작 전에 실제 반복 체험 하나가 필요하다.** 기존 영상이나 현장 10회 운영에서 누락 항목과 복구 시간을 먼저 기록한다. 문제가 없다면 장치를 복잡하게 만들어 문제를 발명하지 않는다.

사진 체크리스트, 기준 영상 차이, 4개 스위치 상태 머신과 비교한다. 동일한 누락을 놓치지 않으면서 설치·매회 확인·재배치 후 재설정 시간을 포함해 줄여야 한다. 학습 모델이 스위치를 못 다는 소품이나 자연스러운 외형 변동에서 이득이 있는지도 확인한다.

**현재 판단: 보류.** 실제 사용처, 단순 방법 대비 이득, AI 기여가 미확인이다. 시연 목적을 개선했지만 추천으로 승격하지 않는다.

## 실행 조건과 선택 순서

[VENTUNO Q 공식 문서](https://docs.arduino.cc/hardware/ventuno-q)는 Linux MPU와 STM32 MCU, USB·센서 연결을 제공한다. 특정 카메라·모델의 호환성과 속도를 실측한 것은 아니다. 행사 이미지에서 카메라 입력과 작은 모델의 ExecuTorch CPU 실행부터 확인한다. NPU 최적화는 필수 경로에 두지 않는다. 선착순 Modulino도 필수 부품으로 가정하지 않는다.

**동시에 세 개를 만들지 않는다.** ResumeStitch의 실제 천 판독과 재개 시간 가설을 먼저 시험한다. 실패하고 이미 쓸 수 있는 분류기를 확보한 경우에만 Live Acceptance를 검토한다. ResetCheck는 실제 운영 사례 확보 전에는 제작하지 않는다.

임계 경로는 **현실 입력 확보 → 반복 관찰 → 단순 대안 → AI 필요성 → 보드 통합 → 효용 비교**다. UI 틀과 보드 런타임 확인은 일부 병렬화할 수 있지만, 모델 평가는 촬영 안정화와 데이터 수집을 기다린다. 팀 인원으로 이 의존성이 사라지지 않는다.

최종 판단은 **사용자 과제를 더 잘 해결하는가**, **그 개선이 온디바이스 AI와 물리 입출력에서 생기는가** 두 축으로 남긴다. 첫 축만 통과하면 좋은 도구일 수 있지만 이번 AI·IoT 출품 근거는 부족하다.
