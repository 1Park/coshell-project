IoT Track 아이디어 검토 — 2026-10-04
==================================

**추천 순서는 Quantization Cliff → Physical CI → SeamBack이다.** 첫 번째는 행사 기술과 맞고, 두 번째는 물리적 시연이 강하며, 세 번째는 사용 장면과 구현 범위가 가장 명확하다. 아래 10개는 설계 검토를 통과한 제안이다. 보드·부품으로 실행하거나 사용자에게 검증한 결과는 아니다.

‘기존에 아무도 하지 않았다’는 보증은 하지 않는다. 공개된 동일 사용 흐름을 찾으면 탈락시키고, 인접 기술만 있는 경우에는 무엇이 다른지 명시했다. 지역·가격·오프라인 실행만 바꾸는 차별화는 인정하지 않았다. 직접 경쟁이 없다는 결론이 아니라, **이번 검색에서 확인한 선행 사례와 구별되는 좁은 구현안**이라는 뜻이다.

**검토 조건**

- 사용자가 인용한 문구는 [ExecuTorch Hackathon 공식 등록 페이지](https://luma.com/executorch-hackathon)와 일치한다. 2026년 10월 17–18일, 샌프란시스코 Founders, Inc., 팀 3–5명, 제안서 마감 10월 4일로 안내된다. 마감 시각·시간대와 실제 개발 가능 시간은 확인되지 않았다.
- 미응답 조건의 가정: 3명, 약 48시간의 행사 구간, 실제 집중 작업 16–20시간/인, 총 48–60 인시. 아래 공수는 견적이며 학습 데이터 수집·기구 제작·통합을 포함한다. 48시간 연속 개발을 공식 일정으로 가정하지 않는다.
- 보드 외 추가 부품의 설계 예산 상한은 약 15만 원/프로젝트. 노트북과 USB 웹캠은 보유 가정. 아래 금액은 구매 견적·실시간 가격이 아니라 설계상 예산 배분이다. 부품 수급과 반입 가능 여부는 아직 미확인이다.
- [VENTUNO Q 공식 문서](https://docs.arduino.cc/hardware/ventuno-q)는 Qualcomm IQ8 MPU와 STM32H5F5 MCU, 최대 40 dense TOPS NPU, USB·Qwiic 등을 명시한다. [공식 스토어](https://store.arduino.cc/products/ventuno-q)에는 16GB RAM·64GB eMMC·USB 카메라 지원이 기재되어 있다. 이 사양으로 특정 모델의 처리 속도를 보장하지 않는다.
- 기본 추론 경로는 VENTUNO의 Linux에서 ExecuTorch + 작은 CNN/MLP 모델이다. [XNNPACK 공식 문서](https://docs.pytorch.org/executorch/stable/ios-xnnpack.html)에 ARM64 Linux 지원이 명시되어 있다. 실제 보드 이미지에서 빌드·런타임 검증은 필요하다.
- [Qualcomm backend 문서](https://docs.pytorch.org/executorch/stable/backends-qualcomm.html)에 Linux embedded 빌드 경로가 있지만 이것만으로 VENTUNO Q의 모든 모델·NPU 조합이 작동한다고 단정하지 않는다. NPU는 행사 제공 환경에서 확인 후 추가한다. CPU 실행만으로 기본 데모를 완성한다.
- MCU는 샘플링, 모터 명령, 제한값, 타임아웃을 담당한다. Linux는 인식·추론·기록을 담당한다. 정확한 RPC/API는 행사 이미지의 예제를 기준으로 확인한다. MCU 펌웨어 루프가 빠르다고 카메라부터 동작까지의 전체 지연이 1ms라고 주장하지 않는다.
- 제공 Modulino 종류는 선착순이고 확정 목록이 없다. [공식 Modulino 라이브러리](https://docs.arduino.cc/libraries/arduino_modulino)와 [Movement](https://docs.arduino.cc/hardware/modulino-movement/) 문서를 참고하되 필수 부품은 직접 확보하는 설계다. Movement는 IMU이며 힘 센서가 아니다. Buzzer는 마이크가 아니다. Thermo는 열화상 카메라가 아니다.

모든 목표 수치는 앞으로 실시할 소규모 데모의 합격 기준 제안이다. 달성한 성능이나 모집단 일반화 수치가 아니다. 여러 영상의 인접 프레임을 무작위로 나누지 않고 촬영 세션·배치·재료별로 학습과 평가를 분리한다.

**1. Quantization Cliff — 모델을 경량화한 뒤 실제로 어디서 판단이 갈리는가**

사용자: 작은 비전 모델을 엣지 장치에 배포하는 개발자. 평범한 테스트 사진에서는 잘되는데 실제 조명이나 물체 각도가 조금 달라지면 경량화 모델만 틀리는 문제를 다룬다.

장치가 물체를 회전시키고 조명을 바꾸면서 같은 프레임을 FP32·INT8 모델에 입력한다. 둘의 출력이 갈라진 조건을 찾고, 그 주변을 좁혀 ‘이 물체, 이 각도, 이 조명’의 재현 가능한 사례를 만든다. 원본 프레임·전처리·모델 해시·실제 측정 조도 또는 설정값·각도·출력을 함께 저장한다. FP32가 무조건 정답은 아니므로 사람이 정한 3개 물체의 정답 라벨도 대조한다.

- **90초 시연:** 정면에서는 두 모델이 같은 판단 → 조명/턴테이블 자동 탐색 → 특정 구간에서 INT8만 오분류 → 정상 위치로 복귀 → 저장된 조건으로 돌아가 같은 차이를 재현.
- **구현 범위:** 물체 3개, 고정 카메라, 회전 1축, 조명 밝기 1축. 실제 카메라 입력만 사용. 범용 VLA 평가·자동 모델 수정·여러 NPU 비교는 제외.
- **AI와 제어:** 작은 MobileNet 계열 분류기의 FP32/INT8 두 버전을 ExecuTorch로 실행. MCU는 회전·밝기 제어. 탐색은 작은 격자 탐색 후 국소 세분화로 충분하다. 불연속적인 경계를 무조건 이분 탐색하지 않는다.
- **데이터:** 3종 물체를 서로 다른 촬영 세션에서 수집. 양자화 calibration 세트와 탐색·평가 세트 분리. 기본 모델도 정확히 구분하지 못하면 클래스 수부터 줄인다.
- **필수 부품:** USB 웹캠, 서보 또는 소형 턴테이블, 별도 전원, 고정 조명·드라이버, 위치 고정 지그. 조도 센서 선택. 추가 예산 배분 5–10만 원.
- **확인할 목표:** 같은 원본 프레임을 두 모델에 넣는지; 발견 조건 5회 재현 중 4회 같은 판단 차이가 나는지; 자동 노출·화이트밸런스를 고정할 수 있는지. 조도 센서가 없으면 PWM 값을 lux로 표기하지 않는다.
- **가장 큰 위험:** 제대로 경량화한 모델에서는 흥미로운 차이가 안 나올 수 있다. 그 자체도 결과다. 시연용으로 calibration을 의도적으로 나쁘게 만든 경우 반드시 fault injection이라고 표시한다. 자연적인 문제를 발견한 것처럼 발표하지 않는다.
- **초반 중단 기준:** 모델 export 두 개와 동일 프레임 비교를 초반 4시간 내 확보하지 못하면 선택 보류. 조명만 바꿨는데 두 모델 모두 같은 이유로 실패하는 데모는 본 아이디어의 성공이 아니다.
- **기존과의 차이:** [VLA metamorphic testing 연구](https://arxiv.org/html/2602.22579v2)는 시뮬레이션 로봇 궤적의 변환 일관성을 평가한다. [공개 경량화 benchmark](https://github.com/nonreaction123/edge-ai-quant-benchmark)는 모델 크기·속도 등의 비교를 다룬다. 여기서는 **두 배포 산출물의 판단 차이를 실제 액추에이터로 찾아, 물리 설정과 함께 재현**하는 것이 핵심이다. 양자화 테스트 자체를 새 발명이라고 주장하지 않는다.
- **판정:** 추천 상위. 행사와 직접 맞고, 범용 로봇 없이 모델·센싱·제어를 모두 보여준다. 실제 불일치 사례가 확보되는지가 선택 조건이다.

추가 비교: [QNNRepair](https://arxiv.org/abs/2306.13793)는 원본·양자화 모델과 성공/실패 데이터로 성능 저하를 찾아 수정하는 연구다. 따라서 모델 간 차이를 찾거나 수정한다는 주장만으로는 신규성이 없다. 이 안의 결과물은 모델 수리 알고리즘이 아니라 **실물·광원·카메라를 포함한 재현 가능한 실패 입력을 자동 수집하는 장치**다.

**2. Physical CI — 물리 장치에 실패 지점과 부분 재시험을 붙인다**

사용자: 과학관 전시나 메이커 교육용 연쇄 장치를 만드는 사람. 마지막 벨이 안 울렸다는 것만 알아서는 어디를 고쳐야 할지 모르고, 전체 장치를 매번 되감는 데 시간이 든다.

‘구슬이 경사로를 지나 플랩을 밀고 종을 친다’는 3단계를 등록한다. 정상 시범에서 각 사건과 시간 간격을 기록하고, 실패하면 처음 달라진 연결을 표시한다. 다음에는 전체 시작점 대신 중간 투입구를 열어 의심 구간만 시험한다. 실제 부분 재시험이 통과해야 복구 완료로 기록한다.

- **90초 시연:** 정상 한 번 → 두 번째 경사로를 살짝 어긋나게 배치 → “구슬은 1번을 통과했고 플랩에는 도달하지 않음” → 중간 게이트만 열어 검증 → 사용자가 정렬 → 부분 테스트와 전체 테스트 통과.
- **구현 범위:** 한 화면에 들어오는 세 단계, 고정된 투입구 두 곳. 사용자가 영역과 기대 순서를 지정한다. 시범 한 번으로 임의 기계의 인과 구조를 완전히 이해한다고 주장하지 않는다. 구슬 리셋은 사람이 한다.
- **AI와 제어:** 작은 영상 모델이 통과·튕김·정지·플랩 상태를 인식한다. 시간 그래프와 최초 불일치 탐색은 명시적 로직. MCU가 두 서보 게이트·LED를 제어한다. 비전이 못 본 사건과 실제 사건 부재를 구분해 ‘관측 불확실’을 둔다.
- **데이터:** 정상·이탈·플랩 미작동 각각 약 15–25개 짧은 실행, 다른 배치를 평가 세트로 보류. 전체 녹화 하나의 수백 프레임을 독립 실행 수백 개로 세지 않는다.
- **필수 부품:** 웹캠, 서보 2개, 골판지 경사로, 구슬, 플랩·벨, 외부 전원. Distance 선택. 예산 배분 4–8만 원.
- **확인할 목표:** 미리 정의한 고장 3종의 12개 독립 실행에서 최초 실패 연결 10개 이상 찾기. 부분 재시험 시 정상 구간의 불필요한 동작을 실제로 줄이기.
- **가장 큰 위험:** 빠른 구슬·가림·자동 리셋 기구가 공수를 늘린다. 넓은 구슬과 짧고 완만한 경사로를 쓰고, 자동 리셋은 만들지 않는다. 마커는 지그 좌표 보정에만 사용한다.
- **초반 중단 기준:** 3단계의 반복 가능한 정상 실행을 3시간 내 못 만들면 메커니즘을 더 단순화. 단순화 후에도 구간별 사건 관측이 안 되면 보류.
- **기존과의 차이:** [Folk Computer의 Marble Run](https://folk.computer/newsletters/2026-07)은 투영된 공이 실제 물체를 따라 움직이는 상호작용 사례다. [Rube Goldberg 프로젝트](https://devpost.com/software/network-over-rube-goldberg-machine)도 존재한다. 여기서는 실제 공이 움직이는 장치의 **사건 기록 → 실패 연결 지목 → 중간 투입으로 가설 검증 → 재시험 보고서**가 결과물이다.
- **판정:** 추천 상위. 관객이 원인·실패·복구를 눈으로 확인할 수 있고 단순 이상 알림보다 기능적으로 깊다.

**3. SeamBack — 한 칸 잘못 꿴 순간을 기록하고, 필요한 만큼만 되돌린다**

사용자: 십자수 입문자. 열 개쯤 진행한 뒤 한 칸 밀린 것을 알면 도안과 실물을 비교하면서 어디까지 풀어야 할지 찾는 일이 어렵다.

장치가 각 칸의 빈 상태·대각선 한 가닥·완성 X·잘못된 위치를 구분하고 시간순으로 저장한다. 지정 도안과 처음 달라지는 순간 짧은 진동을 주며, 복구 모드에서는 실제로 했던 최근 동작을 역순으로 보여준다. 푼 상태를 카메라로 확인한 뒤 다음 복구 단계로 넘어간다.

- **90초 시연:** 큰 격자에 4땀 → 한 칸 옆에 잘못 꿰기 → 알림 → ‘최근 두 동작 되돌리기’ 안내 → 해당 실을 풀면 정상 진행으로 복귀.
- **구현 범위:** 8×8 정도의 큰 플라스틱 캔버스, 굵고 대비 높은 실 한 색, 도안 하나, 매 동작 뒤 손을 잠깐 떼는 조건. 일반 면직물·검은 실·가려진 뒷면 매듭·복수 실의 얽힘은 제외. 최소 복구는 **관측한 한 실의 최근 순서** 안에서만 계산한다.
- **AI와 제어:** 셀별 작은 CNN으로 실 상태 분류, 손 가림 동안 커밋 보류. 도안 대조·undo 스택은 규칙. MCU는 풋버튼·진동 모터·행/열 LED를 처리한다. 바늘을 자동으로 움직이지 않는다.
- **데이터:** 조명 2–3개와 서로 다른 손 위치에서 셀 패치 약 300–500개. 세션을 나눠 평가. 실의 색만 읽는 단순 baseline과 비교한다.
- **필수 부품:** 근접 촬영 가능한 웹캠, 스탠드, 큰 캔버스, 실, 버튼/풋스위치, 진동 모터 또는 Vibro. 예산 배분 3–7만 원.
- **확인할 목표:** 손을 뗀 뒤 1초 이내 판정 목표, 의도적 오류 10개 중 8개 이상 탐지, 정상 20땀에서 불필요한 경고 2회 이하. 평가 전 목표를 고정한다.
- **가장 큰 위험:** 한 땀의 보이는 변화만으로 뒷면 실의 실제 연결 관계를 완벽히 추론할 수 없다. 불명확한 이력은 자동 복구 안내를 중단하고 사용자 확인으로 스택을 교정한다.
- **초반 중단 기준:** 고정 지그와 굵은 실에서도 빈 칸/반땀/X 분류가 구분되지 않으면 제품 범위를 확대하지 말고 보류.
- **기존과의 차이:** [Knyt](https://www.knytstudio.com/progress-tracker)는 사용자가 표시하는 진행 추적을 제공한다. [Pixel Art Adaptation 연구](https://www.is.ocha.ac.jp/~yuki/papers/pixelArtAdaptation_PG2022.pdf)는 제작 오류에 맞춰 패턴을 바꾸며, 해당 논문에서는 오류를 GUI로 입력한다. 여기서는 **실물에서 읽은 동작 이력으로 짧은 복구를 안내하고 복구 상태까지 재인식**한다. 자수 앱이나 도안 생성 자체는 차별점이 아니다.
- **판정:** 가장 현실적인 생활형 후보. 일반 자수 전체를 지원하겠다는 확장만 막으면 작은 데이터로 시연 가능하다.

**4. TouchDebt — 장갑을 갈았는데 왜 다시 더러워졌는지 보여준다**

사용자: 위생 교육을 진행하는 강사. ‘오염된 것에 닿았다’는 경고만으로는 장갑을 바꾸고도 더러운 집게를 다시 잡는 실수를 설명하기 어렵다.

모의 작업대에서 한 물체를 가상의 오염원으로 지정한다. 손→집게→작업물의 접촉 이력을 시간 그래프로 남기고, 새 장갑으로 기존 집게를 잡으면 어떻게 재오염되는지 보여준다. 정해진 작업을 계속하기 위한 세척·도구 교체 순서를 제시하고 그 순서를 따라 하면 모의 상태가 회복된다.

- **90초 시연:** 빨간 토큰 접촉 → 집게 접촉 → 장갑 교체 버튼 → 같은 집게를 잡아 재오염 → 경로 표시 → 집게 교체 후 손 상태 초기화 → 새 작업물이 오염되지 않는 것 확인.
- **구현 범위:** 한 사람, 큰 물체 3개, 모의 오염 1종, 명시적인 교체/세척 확인 버튼. 실제 세균·알레르겐·식품 안전 여부를 영상으로 판정하지 않는다. 실제 위생 자문이 아니라 상태 전파 규칙이 공개된 교육 게임이다.
- **AI와 제어:** 손·물체 영역 및 잡기/놓기 인식은 로컬 모델. 상태 전파·복구 순서는 그래프 탐색. 정전용량 터치 패드나 접촉 스위치를 알려진 소품에 붙여 실제 접촉 근거를 보강한다. MCU는 해당 물체의 LED와 진동 피드백을 출력한다.
- **데이터:** 접촉·근접하지만 미접촉·잡기·교체를 포함한 약 60개 짧은 동작. 영상상의 겹침만으로 접촉이라고 확정하지 않는다. 가린 접촉은 미확정 상태로 둔다.
- **필수 부품:** 웹캠, 소품 3개, 접촉 센서/스위치, 버튼, LED. 예산 배분 4–9만 원.
- **확인할 목표:** 10개 미리 설계한 경로에서 전파 이력과 복구 후 상태가 정답 규칙과 일치. 특히 ‘새 장갑 + 이전 집게’와 ‘깨끗한 집게 + 이전 장갑’ 두 반례 시연.
- **가장 큰 위험:** 접촉 모델이 한 번 틀리면 이후 그래프가 모두 틀어진다. 확정·가능·미관측 상태를 분리하고, 교육자가 수정할 수 있게 만든다. 최소 복구는 정해진 세척 비용과 정해진 다음 작업 안에서만 계산한다.
- **초반 중단 기준:** 실제 접촉과 공중 통과를 센서 결합으로도 구별 못 하면 접촉 센싱부터 재설계. 카메라만으로 해결했다고 주장하지 않는다.
- **기존과의 차이:** [Deep Clean](https://github.com/nickbild/deepclean)은 접촉된 표면을 청소 대상으로 표시한다. [손·표면 위생의 결합 연구](https://pubmed.ncbi.nlm.nih.gov/39191014/)도 있다. 차별점은 **시간순 전파와 재오염을 재현하고, 다음 작업 전에 수행할 복구 순서를 실제 소품으로 연습**하는 것이다. ‘AI 오염 탐지기’라는 이름으로 제출하면 기존성과 과장 문제가 커진다.
- **판정:** 교육 장면이 강한 후보. 실제 오염 감지 제품으로 포장하지 않을 때 구현 경계가 명확하다.

**5. TugMap — 케이블을 뽑지 않고, 어느 끝과 이어지는지 찾는다**

사용자: 작은 공연·촬영·메이커 작업대에서 비슷한 케이블을 정리하는 사람. 단자 종류가 섞여 있거나 연결을 유지해야 할 때 케이블을 한 가닥씩 눈으로 따라가야 한다.

한쪽 케이블 중간에 부드러운 클립을 달고 서보로 아주 작고 느린 패턴의 움직임을 준다. 반대쪽 여러 가닥의 움직임을 카메라로 추적해 어느 가닥이 입력 패턴을 따라오는지 추정한다. 옆 가닥까지 같이 움직이면 다른 패턴을 한 번 더 주고, 계속 애매하면 매핑을 거부한다.

- **90초 시연:** 뒤엉킨 동일 색 케이블 4개 → 원하는 가닥에 클립 → ‘긴 움직임, 짧은 움직임 두 번’ → 반대쪽 후보 표시 → 한 번 더 확인 → 연결표 생성. 이후 두 가닥을 단단히 묶어 ‘판별 불가’도 시연.
- **구현 범위:** 책상 위 짧고 느슨한 4가닥, 카메라에 보이는 반대쪽 자유 구간. 벽 속 배선·단단히 묶인 하네스·장력 걸린 광케이블·실제 공연 중인 장비는 제외. 데모는 전기적으로 연결하지 않은 케이블에서 시작한다.
- **AI와 제어:** 영상 모델은 겹친 케이블의 보이는 구간 분리와 재추적에 사용. 입력 패턴과 변위의 대응은 상관분석·시간 정렬이다. 이를 통째로 신경망 추론이라고 설명하지 않는다. MCU는 제한된 변위의 저주파 서보 움직임을 만든다.
- **데이터:** 5–10개의 다른 배치에서 케이블 영역을 표시한 약 150–250프레임과 약 40번의 구동. 새 배치는 평가용으로 보류한다. 일반 30fps 카메라로 빠른 진동 주파수를 직접 재겠다는 설계는 피한다.
- **필수 부품:** 웹캠, 서보, 탄성 연결부·부드러운 클립, 케이블 4개, 고정 배경. 선택적으로 IMU. 예산 배분 4–8만 원.
- **확인할 목표:** 새 느슨한 배치 10개 중 8개 이상 매핑, 강하게 묶인 5개 사례에서는 오답보다 판별 불가를 출력. 정확도와 응답 거부율을 함께 보고한다.
- **가장 큰 위험:** 신호가 안 전달되거나 모든 가닥이 같이 움직인다. 이 경우 AI로 물리적 정보 부족을 해결할 수 없다. 케이블의 자유 구간을 카메라로 보이게 하는 설치 조건이 필요하다.
- **초반 중단 기준:** 2시간짜리 물리 실험에서 올바른 가닥의 변위가 다른 가닥과 구별되지 않으면 즉시 보류. 소프트웨어를 먼저 만드는 후보가 아니다.
- **기존과의 차이:** [PATCHBOX의 안내](https://patchbox.com/help-center/patchbox/cables/identifying-cable/)도 케이블을 살짝 움직이며 눈으로 추적하는 방법을 설명한다. [PinPath](https://github.com/rwrife/pinpath)는 전기적 연속성을 검사한다. 차별점은 **단자에 접근하지 않고, 코드화된 기계적 자극과 영상의 대응으로 여러 후보를 동시에 판별하며 불확실성을 검사**하는 것이다. 흔들어 찾는 발상 자체는 새롭지 않다.
- **판정:** 기억에 남는 후보지만 구현 위험이 크다. 신호 전달 파일럿을 통과한 경우에만 최종 출품안으로 선택한다.

**6. PackProbe — 완충재를 얼마나 넣을지가 아니라, 어느 방향이 아직 헐거운지 찾는다**

사용자: 형태가 일정하지 않은 중고 물건을 재사용 포장재로 포장하는 소규모 판매자. 상자가 꽉 차 보여도 특정 방향으로 내용물이 움직이고, 종이를 더 넣어도 문제 위치를 못 맞추는 상황이다.

상자를 낮은 진폭으로 기울이거나 왕복시키면서 내용물과 상자 벽의 상대 움직임을 관찰한다. ‘오른쪽 지지가 부족하다’는 식으로 한 곳을 지정하고, 사람이 보강하면 동일한 자극으로 전후를 비교한다. 결과는 이번 시험에서의 상대 변위 감소다.

- **90초 시연:** 외관상 꽉 찬 상자 안 모형이 좌우로 흔들림 → 특정 방향 보강 제안 → 종이 한 조각 추가 → 같은 왕복 시험에서 상대 움직임 감소를 나란히 표시.
- **구현 범위:** 뚜껑을 연 작은 상자, 가벼운 모형 한 개, 상부에서 보이는 표면, 움직임 1축. 종이가 물체를 완전히 가리거나 밀봉한 상자 내부를 추론하는 기능은 제외. 사람이 상자를 90도 돌려 다른 방향을 재시험할 수 있다.
- **AI와 제어:** 로컬 영상 모델이 물체·상자·손·완충재를 구분한다. 안정된 프레임에서 상대 운동을 추적하고 손이 들어오면 시험을 보류한다. MCU는 일정한 왕복/경사 프로파일을 실행하고 IMU로 실제 움직임의 일관성을 확인한다.
- **데이터:** 물체 2종 × 3가지 지지 배치 × 반복 시험으로 약 40–60개 실행. 외곽 마커는 상자 좌표에만 사용한다. 물체 자체의 고정 마커만 따라가면 ML 기여가 약하므로 실제 표면 분리와 비교한다.
- **필수 부품:** 웹캠, 작은 서보 틸트 지그, IMU, 상자·종이·가벼운 모형, 외부 전원. 예산 배분 5–10만 원.
- **확인할 목표:** 같은 자극에서 보강 전후 상대 변위를 재측정. 6개 미공개 포장 배치에서 제안한 보강 후 변위가 감소하는지 확인. 단위 변환은 카메라 좌표 교정 후에만 mm로 표기한다.
- **가장 큰 위험:** 움직임이 없다고 충격 보호가 좋은 것은 아니다. 너무 단단한 포장도 충격을 전달한다. 배송 파손 확률·낙하 안전·ISTA 인증을 주장하지 않는다. 단단한 블록으로 눌러 변위만 없앤 경우를 ‘최적 포장’으로 평가하지 않는다.
- **초반 중단 기준:** 모형과 상자 움직임을 분리해서 측정 못 하거나 반복 자극 자체의 편차가 보강 효과보다 크면 보류.
- **기존과의 차이:** [Ranpak AutoFill/Decision Tower](https://ir.ranpak.com/news/news-details/2025/Ranpak-and-Walmart-Join-Forces-to-Roll-Out-Automated-Technology-and-Sustainable-Packaging-Collaboration/default.aspx)는 비전 기반 빈 공간 측정·완충재 투입을 제공한다. [TransPak](https://www.transpak.com/design/field-data-packaging-analytics/)은 운송 환경 데이터를 포장 설계에 활용한다. 이 후보의 좁은 차이는 **포장하는 바로 그 순간, 재사용 완충재의 지지 부족 방향을 능동 시험하고 수정 효과를 반복 확인**하는 것이다. 일반 ‘AI 포장 최적화’로 확대하면 차별성이 사라진다.
- **판정:** 실용성과 시각적 결과가 좋은 후보. 인접 산업이 강하므로 발표에서 측정 대상과 차별점을 정확히 유지해야 한다.

**7. PatchMatch — 색은 비슷하지만 함께 늘어나지 않는 수선 천을 걸러낸다**

사용자: 리페어 카페나 의류 수선 입문자. 원래 옷과 비슷한 색의 조각을 골랐는데 수선 후 한쪽만 당겨지거나 주름이 생기는 문제를 다룬다.

원단과 후보 자투리를 같은 지그에서 약한 힘으로 조금 늘린다. 카메라가 늘어나는 방향·주름·회복을 보고, 힘 센서가 실제 하중을 잰다. 후보 3개와 방향 2개 중 원래 천과 변형 반응이 가장 가까운 것을 추천한다. 비교적 단단한 같은 색 조각보다 다른 방향으로 놓은 조각이 더 잘 맞는 장면이 핵심이다.

- **90초 시연:** 같은 색 천 A와 B → 원래 천/A/B를 같은 힘 범위에서 시험 → B를 90도 돌리는 조합 추천 → 임시로 결합한 두 조합을 다시 당겨 경계 주름과 변형 차이 비교.
- **구현 범위:** 규격이 같은 직사각형 스와치, 큰 무늬가 있거나 추적 가능한 표면, 한 방향 시험 후 사람이 90도 회전. 완성 의류에 바로 적용·섬유 성분 식별·수명 예측·자동 바느질은 제외. 임시 결합의 결과는 최종 봉제 품질을 보장하지 않는다.
- **AI와 제어:** 영상 모델은 원단 영역·주름·클램프 미끄러짐을 구분한다. 힘–변형 곡선 비교는 수치 계산. MCU가 저속 인장과 하중 상한·이동 범위를 관리한다. 서보 명령 각도를 실제 인장력으로 사용하지 않는다.
- **데이터:** 6–8개 스와치의 정상 인장·클램프 미끄러짐·주름 발생 영상 약 60개. 물리량은 직접 측정하고 이미지로 재료 강도를 상상하지 않는다. 평가에는 학습 때 쓰지 않은 스와치를 남긴다.
- **필수 부품:** 웹캠, 로드셀+ADC, 저속 구동부, 단단한 클램프, 이동량 확인용 눈금/거리 센서, 천. 예산 배분 7–13만 원. 지그 제작 경험자가 필요하다.
- **확인할 목표:** 같은 스와치 반복 시험의 편차가 후보 간 차이보다 작을 것; 클램프 미끄러짐을 재료의 신축성으로 오인하지 않을 것; 선정 결과가 재시험에서도 유지될 것.
- **가장 큰 위험:** 직물은 비선형이고 히스테리시스가 있어 한 숫자로 설명할 수 없다. 동일한 작은 하중 구간의 상승·회복 곡선을 비교하고 충분히 쉬게 한다. 힘을 검증할 수 없으면 ‘기계적 호환성 측정’이라는 주장은 철회한다.
- **초반 중단 기준:** 4시간 내 저하중 인장과 반복 가능한 하중 측정을 확보하지 못하면 선택 보류. 기준 스와치에서 측정 편차 15% 이내를 일차 목표로 잡되, 달성 전 성능으로 쓰지 않는다.
- **기존과의 차이:** [iFixit 수선 가이드](https://www.ifixit.com/Guide/How%2Bto%2Brepair%2Ba%2Bhole%2Bin%2Bwoven%2Btextile%2B%28using%2Ba%2Bself%2Badhesive%2Bpatch%29/169940)는 신축성 등 원단 특성이 맞는 패치를 고르라고 안내한다. [Decathlon의 신축 패치](https://www.decathlon.ca/en/p/self-adhesive-stretch-fabric-repair-patches/355040/m8882541)도 있다. 이 후보는 **성분표가 없는 낡은 천과 현재 가진 자투리의 실제 변형을 현장에서 비교해 방향까지 선택**한다. 직물 시험기 자체가 새롭다는 주장은 하지 않는다.
- **판정:** 소재 재사용 분야의 좋은 탐색안. 기구 교정 경험이 있을 때 선택해야 하며 소프트웨어만 강한 팀의 첫 선택으로는 권하지 않는다.

**8. ReGrip — 로봇 손가락을 자투리로 바꿨다면, 힘 설정도 다시 배워야 한다**

사용자: 교육용·실험용 그리퍼를 급히 고치는 메이커. 정규 부품 없이 손가락을 두꺼운 종이·플라스틱 띠로 교체하면 이전 닫힘 설정이 그대로 통하지 않는 문제다.

사용자가 규격에 맞춰 자른 임시 손가락을 끼운다. 장치는 조금씩 닫고 낮게 당겨보며 미끄러짐·유지·과도한 찌그러짐을 구분한다. 물체별로 ‘안 떨어지면서 지나치게 찌그러뜨리지 않는’ 작동 구간을 찾고, 그런 구간이 없으면 해당 재료를 거부한다.

- **90초 시연:** 단단한 손가락용 기존 설정을 부드러운 종이 손가락에 적용하면 실패 → 작은 시험 3–5번으로 설정 갱신 → 종이컵 또는 스펀지 들기 → 너무 약한 손가락은 ‘가능한 구간 없음’으로 거부.
- **구현 범위:** 고정된 평행 그리퍼 하나, 규격화된 재료 3종, 가벼운 대상 2종, 이동 1축·낮은 높이. 손가락을 로봇이 직접 자르거나 조립하지 않는다. 범용 pick-and-place·복잡한 로봇팔·파괴 강도 추정은 제외.
- **AI와 제어:** 영상 시퀀스 모델이 유지/슬립/압궤 전조의 관측 상태를 분류한다. 탐색은 제한된 닫힘 단계와 재시험. MCU는 위치·하중 상한·타임아웃을 관리한다. 힘 센서를 쓸 때만 힘 값을 표시한다.
- **데이터:** 재료×물체×닫힘 설정의 약 60–90회 짧은 시험. 객체에 붙인 표식만 따라가는 버전과 직접 표면 인식 버전을 구분한다. 재료를 바꾸면 추가 교정 시험이 필요하다는 것을 UX에 드러낸다.
- **필수 부품:** 조립 가능한 서보 그리퍼, 교체용 띠 재료, 웹캠, 로드셀 또는 접촉 압력 센서, 낮은 이동 지그·받침. 예산 배분 8–15만 원. 그리퍼 프레임 확보가 선행 조건이다.
- **확인할 목표:** 보류한 물체·설정 조합에서 고정 설정보다 성공 시험 수가 늘어나는지; 압궤와 슬립을 동시에 피할 수 없는 재료를 실제로 거부하는지. 데모 물체 외의 잡기 성공률은 주장하지 않는다.
- **가장 큰 위험:** 한 번 버텼다고 재료의 피로 수명이 확보된 것이 아니다. 시험마다 변형 누적을 관찰하고, 후보를 선택한 뒤 같은 짧은 시험을 5회 반복한다. 장기 수명·무인 운영은 범위 밖이다.
- **초반 중단 기준:** 안정된 그리퍼를 초반 4시간 내 확보하지 못하면 보류. 로봇팔 제작으로 확대하지 않는다. 고정 설정이 이미 모든 물체에 잘되면 더 복잡한 AI를 얹지 말고 실제 재료 차이가 있는지부터 재검토한다.
- **기존과의 차이:** [그리퍼 강성에 관한 연구](https://ieeexplore.ieee.org/document/9706345/)와 [가변 강성 손가락 연구](https://link.springer.com/article/10.1007/s41315-024-00398-z)는 이미 있다. 이 후보는 **알 수 없는 임시 교체 부품을 장착한 직후, 그 상태에서 가능한 작동 범위를 검증하고 불가능한 교체를 거부하는 복구 절차**에 집중한다. ‘AI가 섬세하게 잡는다’만 보여주면 기존 프로젝트와 구별되지 않는다.
- **판정:** 로봇 경험이 있는 팀에 적합. 차별점을 유지하려면 꼭 손가락 교체 전후 실패·재교정·거부 사례를 모두 시연해야 한다.

최종 반증 검색에서 [MUXI의 교체 그리퍼 사업](https://tech.muxiprecision.com/robot-gripper-finger-solution)도 확인했다. 따라서 손가락 교체·재료 선정이라는 문제 자체도 신규가 아니다. 이 안을 남긴 이유는 주문 제작 서비스가 아닌, **사용자가 이미 끼운 임시 재료를 장치가 시험해 작동 범위를 획득하는 로컬 복구 루프**다. 이것이 빠지면 해당 후보를 탈락시켜야 한다.

**9. Shadow Bargain — 사람은 물체를 움직이고, AI는 빛을 움직인다**

사용자: 과학관·메이커 행사에서 2–3분 안에 참여할 수 있는 물리 협동 게임을 만드는 사람.

테이블 위 출발점과 도착점 사이에 그림자 길을 만들면 된다. 사람은 소품 3개를 배치하고 AI는 한 축의 광원 위치만 바꿀 수 있다. 길을 만들되 중간의 ‘금지 섬’을 그림자로 덮으면 실패다. 사람과 AI는 서로 다른 조작 권한을 가지고 협력한다. 검은 무늬·반투명 소품·실제 그림자가 섞여 AI가 작은 광원 움직임으로 확인할 필요가 생긴다.

- **90초 시연:** 두 소품 사이 길이 끊김 → 사람이 물체를 옮김 → AI가 광원을 움직여 연결 → 금지 섬까지 덮자 다시 작은 조정 → 연결을 확인하고 실제 서보 문이 열림.
- **구현 범위:** 반차광 상자 속 약 A3 작업면, 물체 3개, 광원 위치 1축, 경로 두 개. 복잡한 3D 역설계·완전 자동 해답·주변 전체 공간 인식은 제외. 레이저 대신 확산된 일반 LED를 쓴다.
- **AI와 제어:** 두 관측 프레임과 광원 위치를 이용해 실제 그림자/인쇄 무늬/손을 구분하는 작은 분할 모델. 작은 후보 이동의 결과 예측은 장면 특징을 입력하는 경량 모델로 시도하고, 어려우면 탐색 자체를 순차 실험으로 제한한다. 연결 판정은 그래프 탐색. MCU는 광원 서보와 작은 문을 제어한다.
- **데이터:** 3개 소품의 약 80–120개 배치·광원 조합. 교정용 단색 바탕과 평가용 무늬 바탕을 분리. 단순 밝기 임계값과 실제로 비교한다.
- **필수 부품:** 웹캠, 서보, 광원·확산판, 차광 프레임, 소품, 문용 서보 선택. 예산 배분 5–10만 원.
- **확인할 목표:** 사전 설계한 풀 수 있는 배치 5개 중 4개에서 6회 이내 광원 조정으로 연결; 불가능한 배치에서는 사람이 바꿔야 할 상태로 반환. 게임 승패는 인식 확률 하나만으로 결정하지 않고 지속된 관측을 요구한다.
- **가장 큰 위험:** 밝은 행사장에서는 그림자가 흐리고 광원을 돌리기만 하면 그림자가 충분히 이동하지 않을 수 있다. 광원은 짧은 회전 암 끝에 달아 실제 위치가 변하게 한다. 반차광 지그에서 먼저 작동을 확인한다.
- **초반 중단 기준:** 2시간 안에 광원 이동으로 해결 가능한 퍼즐 두 개를 만들지 못하면 보류. 단색 배경에서 임계값으로 모든 기능이 끝나는 수준이라면 ML을 장식으로 얹지 말고 무늬·반투명 구별 기능을 실제로 검증한다.
- **기존과의 차이:** [Shadow the Shadow](https://ima.shanghai.nyu.edu/projects/capstones/shadow-shadow) 같은 인터랙티브 그림자 작품과 [Night Lights](https://store.steampowered.com/app/590850/Night_Lights/) 같은 광원 퍼즐은 존재한다. 여기서는 **실제 소품과 실제 광원을 사람·AI가 각각 맡고, 제한된 조작권을 가진 협동자로 문제를 푸는 것**이 게임의 핵심이다. 그림자 인터랙션 자체는 새롭지 않다.
- **판정:** 실용 서비스보다 관객 참여·전시를 선호할 때 좋은 후보. AI를 가상 캐릭터 대사로만 넣지 않고 광원을 조작하는 파트너로 만들어야 한다.

**10. BlackBox Duel — AI에게 답을 묻기 전에, 어떤 실험부터 할지 묻는다**

사용자: 과학 교육·AI 리터러시 체험 진행자. AI가 한 장의 사진으로 정답을 맞히는 시연에서 벗어나, 어떤 관측이 부족하며 무슨 실험이 필요한지 보여주는 게임이다.

사람이 겉보기에는 비슷한 바닥 모듈 중 하나를 몰래 넣는다. 예를 들어 자유롭게 미끄러지는 바닥, 거친 마찰면, 자석으로 특정 구간에서 붙잡는 바닥이다. AI는 기울이기·반대 방향 기울이기 등 제한된 실험 세 번을 쓸 수 있다. 관찰 후 아직 수행하지 않은 기울기에서 물체가 멈출지 이동할지 예측하고, 실제로 실행해 승패를 결정한다.

- **90초 시연:** 같은 퍽이 정지한 장면 → “마찰인지 붙잡힌 것인지 아직 모름” → AI가 역방향 시험 선택 → 가설 변화 → 사람과 AI가 다음 기울기 결과에 베팅 → 실제 실행으로 공개.
- **구현 범위:** 눈에 보이는 동일 퍽 하나, 뒤에서 교체하는 바닥 3종, 한 축의 작은 틸트 테이블, 실험 행동 4개 정도. 임의 물리 법칙 발견·미지 재료 식별·상자 속 3D 복원은 제외. ‘일반 과학자 AI’가 아니라 준비된 가설 집합을 구분하는 게임이다.
- **AI와 제어:** 영상 또는 변위 시퀀스를 보는 작은 모델이 각 조건·행동의 결과 분포를 추정한다. 다음 행동은 가설별 예측이 가장 많이 갈리는 것 중 비용이 작은 것을 선택한다. 이 정보량 계산은 명시적 알고리즘이다. MCU는 틸트 각도와 복귀를 실행하고 IMU로 확인한다.
- **데이터:** 바닥 3종 × 행동 4종 × 반복 8회 안팎의 약 96개 실행. 위치를 섞고 세션을 분리한다. 바닥의 색·QR·교체 슬롯 ID를 정답으로 읽지 않도록 가린다. 평가 행동의 세기는 학습값 사이에서 잡는다.
- **필수 부품:** 웹캠, 강성이 있는 소형 틸트 지그, 서보, IMU, 동일 퍽, 교체 바닥·고정된 자석. 예산 배분 5–10만 원.
- **확인할 목표:** 동일한 시작 사진에서 첫 관측만으로 확정하지 않을 것; 12회 게임에서 후속 행동 결과 예측 10회 이상 목표; 항상 같은 시험을 하는 기준선과 비교해 실험 횟수 또는 예측 오류가 줄어드는지 확인.
- **가장 큰 위험:** 세 바닥이 한 번의 같은 기울이기로 모두 구별되면 능동 실험 선택이 불필요해진다. 서로 다른 조건이 같은 반응을 보이는 첫 행동과, 이를 가르는 후속 행동이 실제로 존재해야 한다. 그렇지 않으면 평범한 3종 분류 데모로 퇴화한다.
- **초반 중단 기준:** 3시간 내 ‘첫 관측은 같지만 후속 관측은 다른’ 물리 조건 두 쌍을 만들지 못하면 보류. 학습 모델 성능보다 실험의 식별 가능성을 먼저 확인한다.
- **기존과의 차이:** [Boombox](https://boombox.cs.columbia.edu/)는 소리로 내부 물체를 재구성하고, [다중 모달 능동 지각 연구](https://www.frontiersin.org/journals/neurorobotics/articles/10.3389/fnbot.2018.00022/full)는 유용한 관측 행동을 고른다. 그 원리를 새롭다고 주장하지 않는다. 이 후보의 차이는 **사람이 숨긴 기계적 조건에 대해 AI가 실험 예산을 쓰고, 미실행 행동의 예측을 실제 장치로 검증하는 대결 규칙**이다. 물체 이름 맞히기 게임과 구별한다.
- **판정:** 재미와 설명력이 좋은 실험형 후보. AI의 불확실성과 능동 실험이 실제로 승패를 바꾸도록 설계할 때 가치가 있다.

**개발을 시작한다면 적용할 공통 실행 순서**

1. 초반 0–3시간: 선택 후보의 가장 위험한 물리 전제를 먼저 시험한다. 동시에 작은 모델 하나를 보드에서 ExecuTorch로 실행하고 MCU 입출력 왕복을 확인한다. NPU와 큰 언어 모델을 기다리지 않는다.
2. 다음 3–8시간: 기구를 고정하고 실제 센서 데이터를 수집한다. 정상·실패·미확정 사례를 함께 수집한다. 소규모라도 촬영/실험 세션을 나눈다.
3. 8–14시간: 추론→상태→동작→결과 확인의 한 사이클을 연결한다. UI는 현재 상태·근거·한 가지 다음 행동만 보여준다.
4. 14–18시간: 새 배치·새 세션에서 평가하고 단순 기준선과 비교한다. 이 단계의 실패를 보고 지원 범위를 줄인다.
5. 마지막 시간: 90초 시연을 두 번 이상 반복하고 센서 분리·불확실 입력·타임아웃을 한 번씩 확인한다. 영상 녹화는 실제 데모의 보조 자료로 명시한다.

시간은 각 팀원이 병렬로 일하는 작업 구간 예시다. 실제 행사 운영시간·사전 제작 허용 여부에 따라 재배치해야 한다. 보드에서 모델을 실행하지 못하면 노트북 시연을 VENTUNO 온디바이스 추론으로 소개하지 않는다.

**선택 조언**

- PyTorch·시스템 개발이 강하면 **1번**. 모델 비교가 행사 기술과 직접 연결된다.
- 하드웨어·데모 연출이 강하면 **2번**. 센서뿐 아니라 부분 재시험이라는 분명한 물리 행동이 있다.
- 가장 좁고 구체적인 사용자 경험을 원하면 **3번**. 작은 격자부터 완성할 수 있다.
- 게임·전시를 만들고 싶다면 **9번 또는 10번**. 서로 다른 협동/대결 방식이다.
- 기구 제작 경험이 없다면 **7번과 8번을 우선 선택하지 않는다**. 5번은 케이블 신호 전달 실험을 먼저 통과해야 한다.
